# Feature Specification: 拓扑添加抽屉

**Feature Branch**: `[006-topology-add-drawer]`

**Created**: 2026-08-05

**Status**: Draft

**Input**: User description: "优化添加界面，不再以越来越长的弹窗进行 Add，改为放在最右侧、方便滚动的抽屉式添加界面。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从右侧抽屉添加拓扑资源 (Priority: P1)

实验室用户在拓扑工作区点击“添加”后，从画布最右侧打开添加抽屉，选择节点或网络对象、填写配置并提交。用户在整个过程中仍能看到当前拓扑上下文，不再被居中的长弹窗遮挡，也不会因为表单超过视口而无法访问后续字段。

**Why this priority**: 添加资源是构建拓扑的首要入口；当前弹窗随配置项增长而变得拥挤，直接影响所有节点和网络对象的创建效率。

**Independent Test**: 在一个已有实验室中依次添加 QEMU、Docker、PC、Bridge、NAT Bridge、Lightweight L2 和 Lightweight L3，验证每类资源均可在右侧抽屉中完成配置、提交并出现在拓扑中。

**Acceptance Scenarios**:

1. **Given** 用户正在查看一个可编辑实验室，**When** 用户点击“添加”，**Then** 添加界面从工作区最右侧打开，中央拓扑仍保持可见且视图位置不发生变化。
2. **Given** 添加表单高度超过可用视口，**When** 用户向下滚动，**Then** 只有抽屉内容区域滚动，标题、关闭入口和主要提交操作始终可访问，页面与拓扑画布不随之滚动。
3. **Given** 用户完成有效配置并提交，**When** 创建操作成功，**Then** 抽屉关闭，新资源出现在当前拓扑中并成为当前选中对象。
4. **Given** 用户点击添加后尚未选择资源类型，**When** 抽屉打开，**Then** 用户能清楚区分 QEMU、Docker、PC 和网络对象，并能快速定位目标类型。

---

### User Story 2 - 安全填写长配置表单 (Priority: P2)

用户配置字段较多的 QEMU 或 Docker 节点时，可以在抽屉内连续浏览所有字段、识别默认值和必填项，并在验证失败后快速回到具体错误位置，而不会丢失已填写内容。

**Why this priority**: 抽屉的主要价值是容纳持续增长的配置项；若滚动、校验和数据保留不可靠，改造只会把原有弹窗问题转移到另一个容器中。

**Independent Test**: 使用字段最多的可用设备模板填写完整配置，分别触发必填、格式、范围和后端结构化错误，验证表单值、错误位置和修正流程。

**Acceptance Scenarios**:

1. **Given** 用户已填写长表单的一部分，**When** 用户在抽屉内上下滚动，**Then** 所有已填写值、选项和展开状态保持不变。
2. **Given** 表单包含不可见区域中的无效字段，**When** 用户提交，**Then** 抽屉定位到第一个无效字段，并在对应字段附近显示可理解的中文错误说明。
3. **Given** 后端拒绝创建请求，**When** 结构化失败返回，**Then** 抽屉保持打开、保留用户输入，并显示错误原因和可执行的下一步。
4. **Given** 创建操作正在提交，**When** 用户再次点击提交，**Then** 系统不会创建重复资源，并明确展示当前操作正在进行。

---

### User Story 3 - 可预测地关闭和恢复工作区 (Priority: P3)

用户可以通过明确的关闭入口、键盘或再次点击添加入口来控制抽屉；未保存配置不会被意外丢弃，关闭后原有 Inspector、画布和底部工具区恢复到打开抽屉前的使用状态。

**Why this priority**: 右侧区域已经承担 Inspector 等功能；抽屉必须与现有工作区协作，避免引入新的遮挡、状态丢失或键盘陷阱。

**Independent Test**: 在 Inspector 展开、底部 Console 展开及不同画布缩放位置下打开抽屉，填写未提交内容后分别通过关闭按钮、Escape 和实验室切换离开，验证确认、焦点和布局恢复行为。

**Acceptance Scenarios**:

1. **Given** 用户未修改任何字段，**When** 用户关闭抽屉，**Then** 抽屉立即关闭，焦点返回触发添加操作的控件。
2. **Given** 用户已修改尚未提交的字段，**When** 用户尝试关闭抽屉或切换实验室，**Then** 系统先确认是否放弃更改，取消放弃时继续保留全部输入。
3. **Given** Inspector 在打开抽屉前可见，**When** 用户关闭抽屉，**Then** Inspector 恢复原来的选中对象、展开状态和宽度。
4. **Given** 用户仅使用键盘，**When** 用户打开、填写、提交或关闭抽屉，**Then** 焦点顺序清晰、焦点不会移到抽屉之外的被遮挡控件，所有主要操作均可完成。

### Edge Cases

- 在 1024×768 的最低支持视口中，抽屉不得使标题、主要操作或当前创建状态不可访问。
- 设备模板或镜像切换导致字段数量动态增加时，滚动位置不得跳到页面顶部，当前仍适用的输入不得被无提示清空。
- 用户切换到另一种资源类型或设备模板且已有未保存输入时，系统必须确认会被清除的内容。
- 当前实验室在另一个客户端被删除、归档或发生版本冲突时，抽屉必须保留草稿并展示权威状态冲突，而不是静默创建到错误实验室。
- 创建任务超时、取消或部分失败时，拓扑不得显示无权威资源标识的幽灵节点；抽屉必须提供重试或退出路径。
- 抽屉打开期间收到其他客户端创建、删除或修改资源的事件时，拓扑可以正常更新，但不得覆盖当前客户端的未提交草稿。
- 没有可用镜像版本或模板不可运行时，用户必须在提交前看到不可用原因，不能进入无结果的创建流程。
- 快速连续点击“添加”只能存在一个添加抽屉实例，不能叠加多个遮罩或重复表单。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 拓扑工作区 MUST 使用位于最右侧的添加抽屉替代现有居中添加弹窗。
- **FR-002**: 添加抽屉 MUST 覆盖所有当前可通过图形界面添加的资源类型，包括 QEMU、Docker、PC、Bridge、NAT Bridge、Lightweight L2 和 Lightweight L3，且不得减少现有可配置字段。
- **FR-003**: 抽屉打开时 MUST 保持当前实验室和中央拓扑可识别；打开或关闭抽屉不得修改画布缩放、平移、节点位置、选中资源或共享拓扑状态。
- **FR-004**: 抽屉 MUST 具有独立的垂直滚动区域；抽屉标题、关闭入口和包含主要提交操作的底部操作区 MUST 在长表单滚动期间持续可访问。
- **FR-005**: 抽屉 MUST 提供清晰的资源分类、资源类型名称、用途说明和不可用状态，使用户无需展开全部表单即可找到目标资源。
- **FR-006**: 设备模板和镜像版本选择 MUST 只展示与所选资源类型兼容且当前可用的选项，并清楚说明无可用版本、未就绪或不可运行的原因。
- **FR-007**: 选择资源类型后，抽屉 MUST 展示该类型的完整默认配置；默认值、单位、必填项、只读值和依赖字段 MUST 与实际提交语义一致。
- **FR-008**: 用户在抽屉内滚动、折叠分组或浏览帮助信息时，所有草稿字段 MUST 保持不变。
- **FR-009**: 切换资源类型或设备模板可能清除已填写内容时，系统 MUST 在清除前获得用户确认；取消切换 MUST 保留原草稿。
- **FR-010**: 客户端校验失败时，抽屉 MUST 定位并聚焦第一个无效字段，同时在相关字段附近显示中文错误信息和修正要求。
- **FR-011**: 服务端返回字段错误、版本冲突、配额限制、资源不可用或其他结构化失败时，抽屉 MUST 保持打开、保留草稿并将错误映射到相关字段或全局错误区域。
- **FR-012**: 创建提交期间 MUST 禁止重复提交，并展示明确的进行中状态；重复点击或网络重试不得产生重复资源。
- **FR-013**: 创建成功后，抽屉 MUST 关闭，拓扑 MUST 根据权威实验室状态展示新资源，并将新资源设为当前选中对象；不得依赖整页刷新。
- **FR-014**: 创建失败、取消、超时或部分失败时，拓扑 MUST 与权威状态一致，不得留下幽灵节点、重复节点或无法操作的临时图形。
- **FR-015**: 抽屉存在未提交修改时，关闭抽屉、切换实验室或执行会替换表单的操作 MUST 请求放弃确认；无修改时不得显示多余确认。
- **FR-016**: 关闭抽屉后 MUST 恢复打开前的 Inspector 可见性、宽度、选中对象和工作区焦点，不得导致右侧栏永久消失或重置。
- **FR-017**: 快速连续触发添加操作时 MUST 复用同一个抽屉实例，不得创建多个重叠抽屉、遮罩或提交上下文。
- **FR-018**: 抽屉 MUST 支持键盘打开、导航、提交和关闭，具有可见焦点、正确标签和受控焦点范围；关闭后焦点 MUST 返回原触发控件。
- **FR-019**: 抽屉 MUST 在 1024×768 及以上的受支持桌面视口中保持可用；空间不足时可以扩大占用宽度，但标题、滚动内容和操作区不得被裁切。
- **FR-020**: 抽屉的打开状态、滚动位置、草稿和展开状态 MUST 仅属于当前浏览器客户端，不得同步到其他浏览器、API 或 MCP 客户端。
- **FR-021**: 成功创建的资源及其任务、版本和实际状态 MUST 继续由现有权威创建流程决定；图形界面、HTTP API 和适用的 MCP 客户端最终 MUST 观察到相同资源结果。
- **FR-022**: 本功能 MUST 保持现有创建生命周期、并发版本检查、幂等、超时、取消、恢复、资源所有权和审计语义，不得以纯前端占位状态替代权威结果。
- **FR-023**: 服务重启、浏览器刷新或事件流重连后，已成功创建的资源 MUST 从权威实验室快照恢复；未提交的抽屉草稿默认不跨刷新恢复。
- **FR-024**: 自动化组件测试 MUST 覆盖抽屉开关、独立滚动、长表单、类型切换确认、字段校验、重复提交、成功、失败、冲突、键盘和焦点恢复。
- **FR-025**: 自动化集成和真实浏览器测试 MUST 使用实际创建接口与事件更新验证所有支持资源类型的提交负载、任务终态和拓扑刷新，并在 `10.72.1.7` 验证至少一个 QEMU、一个 Docker、一个 PC 和一个网络对象的完整添加流程。

### Key Entities

- **添加抽屉会话**: 当前浏览器中的临时界面状态，包括目标实验室、所选资源类别、所选模板、草稿、滚动位置、展开分组、提交状态和触发焦点；不会成为共享实验室数据。
- **资源创建草稿**: 尚未提交的节点或网络对象配置，由资源类型、名称、模板或镜像选择及类型专属字段组成。
- **创建操作结果**: 权威创建任务及其资源标识、进度、成功结果或结构化失败，用于驱动抽屉终态和拓扑刷新。

## Delivery and Deployment Constraints *(mandatory)*

- **Local milestone**: 在本地完成抽屉替换、所有资源类型表单接入、组件与真实后端测试，并通过前端类型检查、格式检查、单元测试、浏览器交互测试和相关后端契约测试。
- **Commit evidence**: 将添加抽屉及其测试作为聚焦的里程碑提交，记录提交 SHA、测试命令和测试结果，不混入无关运行时改动。
- **Deployment artifact**: 从干净的里程碑提交构建可复现部署产物，记录版本、候选标识和摘要，并确保产物包含与提交一致的前端资源。
- **Target validation**: 通过正式部署流程发布到 `10.72.1.7`，在新建实验室中使用真实浏览器依次添加至少一个 QEMU、Docker、PC 和网络对象，验证滚动、提交、事件刷新、失败恢复和删除清理。
- **Rollback**: 在部署前记录上一可用提交和产物；回滚后验证旧界面可加载、现有实验室不丢失且创建 API 仍可使用。
- **Target immutability**: Source fixes MUST NOT be made directly on `10.72.1.7`; failed validation returns to the local worktree for tests, a new commit, and redeployment.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在 1024×768、1366×768 和 1920×1080 三种代表性视口中，100% 的支持资源类型均可在不滚动整个页面的情况下完成配置和提交。
- **SC-002**: 使用字段最多的可用设备模板时，用户在任意滚动位置均能在 1 秒内访问关闭入口或主要提交操作。
- **SC-003**: 至少 90% 的首次使用者能够在不查看文档的情况下，于 60 秒内找到目标资源类型并打开其配置表单。
- **SC-004**: 对每一种支持资源类型，连续执行 20 次有效创建时，重复资源、幽灵节点和必须刷新页面才能显示的成功资源数量均为零。
- **SC-005**: 对字段错误、冲突、配额、超时和服务端失败分别执行测试时，100% 的失败均保留适用草稿，并在 2 秒内向用户展示明确原因和下一步。
- **SC-006**: 仅使用键盘的验收流程能够完成打开抽屉、选择资源、填写必要字段、提交、关闭和恢复焦点，阻断性焦点陷阱数量为零。
- **SC-007**: 两个浏览器客户端与一个自动化客户端并发创建资源时，95% 的测试在 3 秒内观察到相同的权威资源、版本和任务终态，且任何客户端的抽屉草稿不会出现在其他客户端。
- **SC-008**: 在 `10.72.1.7` 的真实浏览器验收中，QEMU、Docker、PC 和网络对象四类代表性资源均可通过抽屉成功创建、出现在画布、被选中并完成后续删除清理。
- **SC-009**: 在可用性对比中，至少 80% 的现有用户认为右侧抽屉比原居中长弹窗更容易浏览、定位字段和保持拓扑上下文。

## Assumptions

- 本功能仅替换拓扑工作区中现有“添加资源”入口的呈现与交互，不新增设备类型、模板类型、镜像来源或批量创建能力。
- 右侧抽屉在打开期间临时覆盖或占用右侧 Inspector 区域；关闭后恢复原 Inspector 状态，而不是同时压缩出两个并列右栏。
- 成功创建后默认关闭抽屉并选中新资源；连续批量添加不属于本次范围。
- 未提交草稿默认不跨浏览器刷新保存，但在同一次抽屉会话内必须可靠保留。
- 后端创建接口、任务模型、资源版本和事件协议继续作为权威来源；本功能不要求改变现有 API 或 MCP 合同。
- 最低支持视口继续遵循现有桌面工作区要求；小于 1024×768 的移动端专用布局不属于本次范围。
