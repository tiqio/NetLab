# Feature Specification: Topology Interaction UX

**Feature Branch**: `[004-topology-interaction-ux]`

**Created**: 2026-07-27

**Status**: Draft

**Input**: User description: "优化拓扑图的滚轮、拖动、主机与 Docker 节点显示、连线逻辑，修复当前不顺手和潜在缺陷。"

## Clarifications

### Session 2026-07-27

- Q: 链路应仅自动走线，还是允许调整并保存控制点？ → A: 自动走线并允许调整控制点，但自定义路径仅保存在当前浏览器。
- Q: 节点、链路和运行状态是否应在不同客户端之间共享？ → A: 必须全局共享；浏览器、HTTP API 和 MCP 编排同一实验室时都能看到相同节点、链路、任务和运行状态，且任何客户端操作都不得使其他客户端会话失效。
- Q: 节点在画布上的坐标是否跨客户端共享？ → A: 共享；一个客户端确认节点位置后，其他客户端同步显示相同坐标。
- Q: 用户将连线拖到节点主体而非具体端口时如何选择目标？ → A: 节点仅有一个可用端口时自动选择；有多个可用端口时显示端口选择器并等待用户确认。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 自然浏览和整理拓扑 (Priority: P1)

实验人员可以像使用常见网络拓扑工具一样缩放、平移和移动节点，不会因为滚轮、拖动或点击手势冲突而误选、误连或移动整个页面。

**Why this priority**: 浏览和布置是所有拓扑操作的基础；如果画布无法稳定控制，后续节点和链路操作都会变得低效且容易出错。

**Independent Test**: 在包含多个节点和链路的实验室中，仅通过鼠标、触控板或键盘完成缩放、平移、节点移动、框选和视图复位，并验证拓扑数据未被意外修改。

**Acceptance Scenarios**:

1. **Given** 指针位于拓扑画布上，**When** 用户滚动滚轮或执行触控板缩放，**Then** 视图以指针附近为视觉中心平滑缩放，并保持在规定缩放范围内。
2. **Given** 用户从画布空白处开始拖动，**When** 指针移动超过拖动阈值，**Then** 仅平移画布，不移动节点、不创建链路且不触发资源选择。
3. **Given** 用户从节点主体开始拖动，**When** 用户释放节点，**Then** 仅该节点或已选节点组移动到新位置，位置被保存、向其他客户端同步并在刷新后保持。
4. **Given** 用户快速点击、双击或轻微抖动指针，**When** 位移未超过拖动阈值，**Then** 系统按点击操作处理，不产生意外移动。
5. **Given** 用户使用最小支持视口，**When** 执行缩放、平移和视图复位，**Then** 所有主要控件均可见、可达且不遮挡拓扑关键内容。

### User Story 2 - 准确创建和调整链路 (Priority: P1)

实验人员可以清楚看到节点端口，从源端口拖到目标端口或依次选择两个端口来创建链路，并能安全断开或重连链路。

**Why this priority**: 连线是网络拓扑的核心工作流，错误端口、重复链路和不明确的连接状态会直接导致实验配置错误。

**Independent Test**: 创建两个具有多个端口的节点，通过拖拽和键盘两种方式分别连接、取消、断开和重连链路，并从刷新后的权威拓扑确认最终端点。

**Acceptance Scenarios**:

1. **Given** 用户开始连接操作，**When** 源端口被选中或开始拖拽，**Then** 系统持续突出源端口、可用目标端口和当前临时连线，并提供明确的取消方式。
2. **Given** 用户将临时连线放到有效且空闲的目标端口，**When** 用户确认连接，**Then** 系统只创建一条链路并显示处理中、成功或失败终态。
3. **Given** 目标端口不可用、与源端口相同或连接违反约束，**When** 用户尝试完成连接，**Then** 系统阻止提交并在目标附近解释原因，源端口选择保持可恢复。
4. **Given** 用户选择现有链路，**When** 执行断开，**Then** 系统要求适当确认、显示操作进度并在成功后释放两个端口。
5. **Given** 用户重连现有链路的一端，**When** 新连接失败或发生版本冲突，**Then** 原链路保持有效或被权威状态恢复，不出现半连接状态。
6. **Given** 多条链路共享相邻节点或端点区域，**When** 用户查看或选择其中一条，**Then** 每条链路仍可辨认、可选择且不会遮住端口操作。
7. **Given** 用户将临时连线放到节点主体，**When** 该节点只有一个可用端口，**Then** 系统自动选择该端口；当存在多个可用端口时，系统显示可用端口选择器且不提前提交连接。

### User Story 3 - 一眼识别节点和状态 (Priority: P2)

实验人员可以通过一致且清晰的图形、名称、运行类型和状态识别 QEMU 主机、Docker 容器、PC、网桥、NAT 网桥和交换机，而无需逐个打开检查器。

**Why this priority**: 视觉辨识度能降低大型拓扑的认知负担并减少对错误节点执行操作的概率。

**Independent Test**: 在同一画布展示所有支持的资源类型和各类状态，由用户仅凭画布准确识别资源类型、名称、选中状态、运行状态和异常状态。

**Acceptance Scenarios**:

1. **Given** 画布包含 QEMU 主机与 Docker 容器，**When** 用户查看拓扑，**Then** 两类节点使用明显不同、风格一致且具有文字补充的图形表示。
2. **Given** 节点处于启动中、运行、停止、失败或删除中，**When** 状态变化，**Then** 节点在不依赖颜色的情况下显示可辨认状态，并与权威状态一致。
3. **Given** 节点具有多个端口，**When** 节点被选中、悬停或进入连线模式，**Then** 端口名称、连接状态和可用性清晰可见；普通浏览时不过度遮挡画布。
4. **Given** 图形资源来自外部设计来源，**When** 产品分发，**Then** 每项资源具有可核验来源和允许产品使用的许可，且产品不依赖运行时访问外部站点。

---

### User Story 4 - 高效选择与键盘操作 (Priority: P2)

实验人员可以选择单个或多个节点和链路、框选资源、清除选择，并使用键盘完成与指针操作等价的主要工作流。

**Why this priority**: 精确选择支持批量布局和无障碍使用，也能减少拖动密集拓扑时的误操作。

**Independent Test**: 在桌面和最小支持视口，通过指针与键盘分别完成单选、增量多选、框选、移动、连接、取消和打开检查器。

**Acceptance Scenarios**:

1. **Given** 画布包含重叠或相邻资源，**When** 用户单击、增量选择或框选，**Then** 选择结果明确且遵循一致的添加、移除和清空规则。
2. **Given** 多个节点被选中，**When** 用户拖动其中一个选中节点，**Then** 整组节点保持相对位置共同移动，链路随节点实时更新。
3. **Given** 用户仅使用键盘，**When** 在资源和端口间导航，**Then** 焦点始终可见，并可完成连接、断开、移动、取消和打开操作面板。
4. **Given** 用户按下取消键或点击空白区域，**When** 存在临时连线、框选或选择状态，**Then** 系统按明确优先级取消临时操作而不修改拓扑。

---

### User Story 5 - 在并发和故障后保持共享可信 (Priority: P3)

多个浏览器或自动化客户端同时编辑同一实验室时，每个客户端都能看到共享节点、链路、任务和运行状态的有序更新；断线、刷新、超时或冲突后，画布能够恢复到共享权威状态。

**Why this priority**: 消除 EVE-NG 按账户隔离节点状态和 API 操作导致浏览器会话失效的问题，是本产品的核心目标；视觉状态也不能与共享实际网络资源长期分离。

**Independent Test**: 使用两个浏览器和一个自动化客户端并发移动节点、启动节点与修改链路，注入冲突和连接中断，再验证所有客户端最终显示相同资源、任务和运行状态，所有会话保持有效且没有孤立资源。

**Acceptance Scenarios**:

1. **Given** 两个浏览器与自动化客户端打开同一实验室，**When** 任一客户端创建、移动、启动或连接资源，**Then** 其他客户端按事件顺序看到相同资源、任务和运行状态，且现有会话保持有效。
2. **Given** 提交时资源版本已变化，**When** 服务拒绝过期修改，**Then** 用户看到冲突说明并可重新加载、重试或放弃，同时保留可安全恢复的操作意图。
3. **Given** 浏览器在链路操作期间断线或刷新，**When** 重新连接，**Then** 临时交互状态被清理，持久拓扑从共享权威状态重建，并明确显示仍在进行的操作。
4. **Given** 链路创建、删除或重连部分失败，**When** 后台操作到达终态，**Then** 所有客户端显示相同终态，失败产生可审计结果且不遗留孤立接口或链路。

### Edge Cases

- 画布为空、仅一个节点、超过一百个节点或存在大量交叉链路时，导航和选择仍需可控。
- 滚轮事件发生在画布、侧栏、弹窗、下拉菜单或页面边缘时，只影响用户当前操作区域。
- 节点拖到画布边界、视口之外或其他节点上时，系统保持节点可恢复且不会永久丢失。
- 用户在拖动节点过程中切换实验室、刷新页面、按取消键或失去窗口焦点时，不提交不完整位置。
- 连线过程中源节点被删除、端口状态变化、另一客户端抢先连接目标端口或操作超时时，系统终止临时连线并刷新权威状态。
- 自连接、重复端点组合、重复提交、反复双击和高延迟情况下，不创建重复链路。
- 平行链路、短链路、环回链路和双向流量标记不能导致链路无法选择或含义混淆。
- 图形资源加载失败时，使用可辨认的本地后备图形与文字，不出现空白节点。
- 用户启用减少动态效果、浏览器缩放或高对比度模式时，主要交互仍然可用。
- API 或 MCP 在浏览器会话打开期间编排拓扑时，浏览器会话不得失效、被替换或停止接收共享状态更新。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供一致的滚轮、触控板和键盘缩放行为，以指针或当前焦点附近为视觉中心，并限制最小与最大缩放级别。
- **FR-002**: 系统 MUST 区分空白画布平移、节点拖动、框选、点击选择和端口连线手势，并使用足以避免轻微指针抖动触发拖动的阈值。
- **FR-003**: 系统 MUST 在平移、缩放和拖动期间提供连续视觉反馈，且这些纯视图操作不得修改节点生命周期或网络连接。
- **FR-004**: 系统 MUST 将已确认的节点坐标保存为共享实验室状态并同步给所有客户端；用户视图中心和缩放级别作为当前浏览器偏好保存，并在刷新、重新打开实验室和重新连接后分别恢复。
- **FR-005**: 系统 MUST 提供适应全部资源、恢复默认视图以及将选中资源置于可见区域的操作。
- **FR-006**: 系统 MUST 为 QEMU 主机、Docker 容器、PC、网桥、NAT 网桥、二层交换机和三层交换机提供不同且一致的视觉表示，并同时显示资源名称和运行类型。
- **FR-007**: 系统 MUST 以不只依赖颜色的方式显示节点的期望状态、实际状态、处理中状态、失败状态和选中状态。
- **FR-008**: 系统 MUST 在普通浏览、悬停、选择和连线模式之间逐级展示端口信息，确保端口可发现且不会在大型拓扑中造成持续遮挡。
- **FR-009**: 系统 MUST 使用具有明确来源、许可和本地后备方案的图形资源，不得因外部资源不可用而使节点无法识别。
- **FR-010**: 用户 MUST 能通过端口拖拽、拖到节点主体和依次选择端口三种方式创建链路，并能使用键盘完成等价操作。
- **FR-011**: 系统 MUST 在连线期间显示源端口、有效目标、无效目标、临时链路和取消方式；拖到仅有一个可用端口的节点主体时自动选择该端口，存在多个可用端口时显示选择器；提交前必须阻止自连接、不可用端口和重复连接。
- **FR-012**: 系统 MUST 为链路创建、断开和重连提供可见的待处理身份、进度、成功或结构化失败终态，并在终态后刷新权威拓扑。
- **FR-013**: 链路重连 MUST 保持原连接有效，直到替代连接被权威状态接受；失败、取消、超时或冲突不得留下半连接拓扑。
- **FR-014**: 系统 MUST 默认自动计算可辨认、可选择的链路路径，并允许用户调整链路控制点；自定义控制点仅作为当前浏览器的视图偏好保存，不得改变共享链路端点或其他客户端的默认路径。
- **FR-015**: 系统 MUST 支持单选、增量多选、框选、全选适用资源和清除选择，并为每种选择状态提供明确反馈。
- **FR-016**: 移动多选节点 MUST 保持其相对布局，并作为一个可撤销或可明确恢复的用户操作处理。
- **FR-017**: 所有主要画布、节点、端口和链路操作 MUST 具有指针与键盘等价路径，焦点可见且确认控件在支持视口中不被裁切。
- **FR-018**: 系统 MUST 定义取消优先级，使取消键依次终止临时连线、框选或拖动、弹出层和当前选择，而不会提交意外修改。
- **FR-019**: 包括节点坐标在内的共享拓扑状态 MUST 使用版本检查处理并发修改；过期写入不得静默覆盖较新的权威状态，也不得使其他客户端会话失效。
- **FR-020**: 浏览器、HTTP 自动化和适用的 MCP 操作 MUST 通过相同的拓扑命令语义创建、启动、停止、断开和重连资源，并最终观察到相同资源版本、端点、任务和运行状态。
- **FR-021**: 系统 MUST 向所有查看同一实验室的客户端发布有序的节点、链路、任务和资源状态变化，并在事件缺失、乱序或重连时重新获取共享权威快照。
- **FR-022**: 画布在加载、空、过期、重连、冲突、部分失败、权限不足、配额不足和成功状态下 MUST 提供可区分且可恢复的用户反馈。
- **FR-023**: 重载或异常中止 MUST 清理仅存在于客户端的拖动、框选和临时连线状态，不得创建持久资源或改变运行节点状态。
- **FR-024**: 删除实验室、节点或链路后，系统 MUST 清理由该资源拥有的运行资源、布局、端口选择和临时连线记录，并在所有客户端恢复后不再显示幽灵资源。
- **FR-025**: 系统 MUST 记录链路及坐标修改的请求身份、资源身份、版本、终态和结构化错误，但不得记录控制台输出、数据包内容、凭据或其他敏感资料。
- **FR-026**: 系统 MUST 限制单次交互产生的更新频率和持久化工作量，使连续拖动不会产生无界任务、事件或存储记录。
- **FR-027**: 系统 MUST 为高密度拓扑提供逐级细节、稳定标签和避免持续遮挡的策略，同时不隐藏选中资源、失败资源或正在连接的端口。
- **FR-028**: 图形和交互变更 MUST 经过桌面与最小支持视口上的真实浏览器回归测试，覆盖滚轮、触控板等价输入、拖动、选择、连线、刷新、并发冲突和故障恢复。

### Key Entities

- **Topology View State**: 某实验室的视图中心、缩放级别、当前选择、临时交互模式以及恢复状态；临时状态与持久状态必须明确区分。
- **Node Placement**: 节点在拓扑中的已确认位置、版本和最后修改来源，关联一个实验室和一个节点。
- **Visual Resource Representation**: 资源类型、显示名称、图形类别、运行状态、选中状态、警告状态和可见端口摘要。
- **Connection Gesture**: 尚未提交的源端口、候选目标、输入方式、开始时间和取消原因，不属于持久拓扑资源。
- **Topology Link**: 两个权威端口之间的连接及其版本、期望状态、实际状态、操作任务和结构化错误。
- **Interaction Preference**: 用户或浏览器范围内的缩放速度、减少动态效果、标签密度和其他非权威视图偏好。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 至少 95% 的测试用户能在首次尝试中完成“缩放到目标节点、移动节点并恢复全图视图”，且全程不发生误连线或误移动。
- **SC-002**: 至少 95% 的有效滚轮、平移、拖动、选择和端口悬停操作在 100 毫秒内出现可见反馈。
- **SC-003**: 在包含 100 个节点和 200 条链路的代表性拓扑中，连续平移、缩放和节点拖动期间，至少 95% 的交互窗口保持流畅且无超过 250 毫秒的可感知冻结。
- **SC-004**: 用户使用指针或键盘均能在 30 秒内正确连接指定的两个端口，并且 100 次重复测试中不产生重复链路或错误端点。
- **SC-005**: 在所有支持的资源类型和状态组合中，测试用户无需打开检查器即可达到至少 90% 的节点类型和状态识别准确率。
- **SC-006**: 桌面和最小支持视口上的全部主要交互均可到达、焦点可见，并且确认、取消和错误恢复控件的裁切率为 0%。
- **SC-007**: 两个浏览器与一个自动化客户端并发修改同一拓扑后，100% 的测试运行在 5 秒内收敛到相同节点、链路端点、资源版本、任务和运行状态，且会话失效数量为零。
- **SC-008**: 对链路创建、断开和重连分别注入失败、超时、取消、冲突和刷新后，100% 的测试运行均恢复到有效权威拓扑，孤立链路和幽灵端口数量为零。
- **SC-009**: 页面刷新、浏览器重连和服务重启恢复后，已确认节点位置与链路保持率为 100%，仅客户端临时交互残留数量为零。
- **SC-010**: 拓扑交互相关的真实浏览器回归套件连续运行两次时，交互清单、终态、并发结果和清理结果不存在无法解释的差异。
- **SC-011**: 在可用性测试中，至少 80% 的参与者认为新版拓扑操作不低于其熟悉的主流网络模拟器，并明确报告滚轮、拖动和连线行为“可预测”。

## Assumptions

- 本功能优化现有单机实验室拓扑工作区，不新增设备类型、认证、多节点集群或新的运行时模拟能力。
- 滚轮位于拓扑画布上时默认执行缩放；空白区域拖动执行平移；节点主体拖动执行节点移动；端口拖动执行连线。
- 实验室、节点坐标、链路端点、运行状态、任务和事件是所有客户端共享的权威状态；画布中心、缩放、标签密度和手动链路控制点属于当前浏览器的视图偏好；临时拖动和临时连线不属于持久状态。
- 现有资源版本、异步任务、事件流和资源所有权规则继续作为跨浏览器、HTTP API 和 MCP 的权威并发与恢复机制。
- 外部图形素材仅作为设计参考或经许可后随产品本地分发，不在用户操作期间从第三方站点动态加载。
- 主要测试输入为鼠标和键盘；触控板必须支持与滚轮、平移和缩放等价的常见行为。

## Dependencies

- 依赖现有实验室、节点、接口、链路、任务、事件和拓扑快照能力。
- 依赖节点模板和运行状态能够提供稳定的资源类型与状态信息。
- 依赖前端交互验收功能维护稳定的交互清单、双视口执行、并发客户端观察和失败清理证据。

## Out of Scope

- 新增 Cisco 或其他设备模板及镜像获取流程。
- 修改 QEMU、Docker、网络命名空间或节点生命周期的运行语义。
- 三维拓扑、自动物理布线推断、跨实验室连线或多用户权限系统。
- 在拓扑画布内展示或保留数据包内容、控制台输出或客体命令输出。
- 依赖未经许可的厂商图标、远程图标服务或复制其他网络模拟器的专有素材。
