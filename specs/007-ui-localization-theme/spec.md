# Feature Specification: 全页面中文化与明暗主题

**Feature Branch**: `[007-ui-localization-theme]`

**Created**: 2026-08-06

**Status**: Draft

**Input**: User description: "针对整个页面做中文化适配，同时为整个界面增加白天/黑夜样式切换功能。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 使用完整中文界面操作网络实验室 (Priority: P1)

中文用户进入系统后，可以在实验室、拓扑、资源添加、节点设置、任务、Console、抓包、Traffic Filter、模板、自动化和诊断等页面看到一致、清晰的中文界面，无需在同一操作流程中反复理解中英文混排的按钮、状态和错误提示。

**Why this priority**: 当前页面仍存在大量英文标题、按钮、状态和说明，直接增加学习成本，并容易让用户误解高风险操作或任务状态。

**Independent Test**: 从实验室创建开始，依次完成添加资源、启动节点、打开终端、创建链路、查看任务、发起抓包和删除资源；整个流程中的产品自有文案均为中文，且关键操作含义明确。

**Acceptance Scenarios**:

1. **Given** 用户首次打开系统，**When** 用户浏览顶部导航、实验室工具栏、设备目录、拓扑画布、Inspector 和底部操作区，**Then** 所有产品自有标题、按钮、菜单、占位文本、状态和帮助说明均使用中文。
2. **Given** 用户执行创建、修改、启动、停止、删除、连接、抓包或过滤操作，**When** 操作成功、进行中、失败、超时或冲突，**Then** 系统以中文展示当前状态、原因和下一步建议，同时保留必要的资源标识、协议名和错误代码。
3. **Given** 用户打开模板、自动化或诊断页面，**When** 页面加载、为空或加载失败，**Then** 页面显示一致的中文加载态、空态、错误态和重试入口。
4. **Given** 页面展示用户输入、设备输出、命令、IP 地址、接口名、协议缩写、镜像名称或厂商型号，**When** 这些内容出现，**Then** 系统保留原始内容，不进行可能改变技术含义的翻译。

---

### User Story 2 - 在白天与黑夜主题间切换 (Priority: P2)

用户可以根据环境光线和个人偏好，在浅色与深色主题之间快速切换；切换后整个应用立即保持一致，不出现局部仍使用旧主题、文字难以阅读或图形语义丢失的问题。

**Why this priority**: 网络实验室通常长时间使用，明暗主题可以降低视觉疲劳；统一主题也能避免拓扑、图表、终端和弹层之间出现割裂感。

**Independent Test**: 在任意页面切换浅色和深色主题，检查导航、面板、表单、弹窗、抽屉、拓扑图、图表、状态色和底部工作区是否同步更新，并在刷新后保持选择。

**Acceptance Scenarios**:

1. **Given** 用户尚未保存主题偏好，**When** 首次打开系统，**Then** 系统采用当前设备的明暗外观偏好；设备未提供明确偏好时采用深色主题。
2. **Given** 用户正在任意页面或打开抽屉、弹窗、Console、Capture、Traffic Filter，**When** 用户切换主题，**Then** 当前页面和所有已打开浮层立即同步切换，且不刷新页面、不关闭会话、不改变拓扑状态。
3. **Given** 用户选择了浅色或深色主题，**When** 用户刷新页面、重新打开浏览器或进入另一个实验室，**Then** 当前浏览器继续使用该主题。
4. **Given** 两个浏览器客户端同时使用系统，**When** 两个客户端分别选择不同主题，**Then** 两者主题互不影响，已创建资源和运行状态仍保持共享一致。

---

### User Story 3 - 在两种主题下保持可读性与可访问性 (Priority: P3)

用户无论使用键盘、鼠标还是辅助技术，都能在浅色和深色主题下识别焦点、状态、选中项、警告、连线方向和流量高亮，不依赖单一颜色判断含义。

**Why this priority**: 主题切换若只替换背景色，容易造成文本、图标、图表、拓扑连线和状态颜色对比不足，形成新的可用性问题。

**Independent Test**: 分别在浅色和深色主题下，仅使用键盘完成导航、打开抽屉、选择资源、提交表单和关闭确认；检查焦点、标签、状态以及拓扑和图表可读性。

**Acceptance Scenarios**:

1. **Given** 用户使用键盘操作，**When** 焦点经过导航、按钮、表单、菜单、标签页、拓扑资源和确认对话框，**Then** 两种主题下均有清晰可见的焦点指示。
2. **Given** 页面展示成功、运行中、警告、失败、选中、禁用或流量方向，**When** 用户切换主题，**Then** 状态仍通过颜色之外的文字、图标、线型或形状表达。
3. **Given** 用户正在查看拓扑、资源图表或流量效果，**When** 切换主题，**Then** 背景、文字、网格、节点、连线、箭头、粒子和高亮具有足够区分度，且不改变图形位置、缩放或数据。
4. **Given** 用户启用了减少动态效果偏好，**When** 切换主题或查看状态变化，**Then** 系统避免不必要的闪烁和大幅动画，同时保留状态反馈。

### Edge Cases

- 浏览器禁止或无法使用本地存储时，主题切换在当前页面仍然有效，并给出非阻塞提示；刷新后允许回到系统默认主题。
- 操作系统主题在页面打开期间发生变化时，仅在用户未明确选择主题时跟随变化；用户已明确选择后不得被系统偏好覆盖。
- 页面在资源加载中、任务执行中、弹窗确认中或 Console 会话连接中切换主题时，不得中断原操作或清空表单。
- 后端返回英文错误、设备原始输出或第三方专有名称时，界面应提供中文上下文或下一步提示，但不得篡改原始技术内容。
- 文本变长后，1024×768 视口中的导航、工具栏、表格、抽屉和右键菜单不得遮挡关键操作；允许换行、截断并提供完整内容查看方式。
- 浅色主题下不能使用仅适合深色背景的固定浅色文字；深色主题下不能出现不可读的固定深色文字。
- 页面刷新或事件流重连后，主题和界面语言状态不得影响实验室、节点、链路、任务、Console、Capture 或 Traffic Filter 的权威状态恢复。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 将全部用户可见的产品自有界面文案统一为简体中文，包括导航、页面标题、按钮、菜单、字段标签、占位文本、提示、确认、空态、加载态、状态和错误说明。
- **FR-002**: 中文化范围 MUST 覆盖实验室管理、设备目录、资源添加、拓扑画布、右键菜单、Inspector、节点生命周期、设置、Console、VNC、Capture、Wireshark 集成、Traffic Filter、任务、诊断、模板、镜像、自动化和 MCP 操作说明页面。
- **FR-003**: 系统 MUST 保留用户数据、资源名称、命令与输出、IP/MAC 地址、接口名、协议缩写、镜像标签、厂商名称、型号、错误代码和资源标识的原始内容。
- **FR-004**: 对无法安全翻译的后端或设备原始错误，系统 MUST 在保留原文的同时提供中文上下文、影响和可执行的下一步建议。
- **FR-005**: 相同概念 MUST 使用统一中文术语；启动/停止、期望状态/实际状态、接口/链路、抓包/流量过滤等核心术语不得在不同页面使用冲突译法。
- **FR-006**: 所有高风险操作 MUST 使用明确的中文动作名称、对象名称、影响范围和二次确认，不得仅显示含糊的“确定”或未翻译按钮。
- **FR-007**: 系统 MUST 提供浅色主题和深色主题的全局切换入口，并在所有主要页面保持可发现且可通过键盘操作。
- **FR-008**: 首次访问且没有明确主题偏好时，系统 MUST 跟随设备外观偏好；无法判断时 MUST 使用深色主题。
- **FR-009**: 用户明确选择的主题 MUST 仅保存在当前浏览器客户端，并在刷新、重开浏览器和切换实验室后继续生效。
- **FR-010**: 不同浏览器客户端 MUST 可以独立使用不同主题；主题选择不得通过实验室状态、HTTP API、MCP 或事件流同步。
- **FR-011**: 主题切换 MUST 即时作用于当前应用的导航、面板、表单、表格、弹窗、抽屉、菜单、提示、代码区域、Console 外壳、拓扑画布和图表。
- **FR-012**: 主题切换 MUST NOT 刷新页面、中断 Console/VNC/Capture/Traffic Filter 会话、取消任务、清空草稿、改变实验室选择或修改拓扑视口与资源位置。
- **FR-013**: 浅色和深色主题 MUST 对成功、运行中、警告、失败、选中、禁用、焦点和流量高亮提供一致语义，且不得只依赖颜色传达关键状态。
- **FR-014**: 两种主题下的正文、辅助文字、表单边界、焦点、按钮、菜单、弹层和状态提示 MUST 满足受支持桌面环境的可读性与无障碍对比要求。
- **FR-015**: 拓扑节点、网络对象、端口、链路、方向箭头、流量粒子、选择框、分组框和画布背景 MUST 分别适配两种主题，切换时不得改变拓扑数据、坐标、路由点或缩放。
- **FR-016**: 图表的标题、坐标轴、网格、图例、提示框、数据系列和空态 MUST 适配两种主题，并在主题变化后保持数据和交互状态。
- **FR-017**: Console 和 VNC 内容区域 MUST 尊重其终端或远程画面的原始配色；主题切换仅调整外围工具栏、标签、边框和状态区域，不得强制改写客户机画面。
- **FR-018**: 系统 MUST 支持减少动态效果偏好；主题切换不得产生强烈闪烁，状态变化动画和流量效果必须在该偏好下保持舒适且可识别。
- **FR-019**: 中文文案变长时，系统 MUST 在 1024×768、1366×768 和 1920×1080 视口下保持关键操作可达，不得因截断、溢出或重叠导致无法完成操作。
- **FR-020**: 用户通过键盘 MUST 能打开主题切换入口、选择主题、关闭入口并恢复焦点；所有主题控件必须具有中文可访问名称和可见焦点。
- **FR-021**: 页面加载期间 MUST 在主要内容绘制前应用最终主题，避免出现明显的错误主题闪烁。
- **FR-022**: 页面刷新、服务重启和事件流重连后，主题偏好 MUST 独立恢复；实验室和运行资源仍由现有权威状态恢复，不得受主题或文案层影响。
- **FR-023**: 本功能 MUST NOT 改变现有资源生命周期、共享状态、并发版本、幂等、任务、审计、API 或 MCP 数据合同；自动化客户端继续收到稳定的机器可读字段和状态值。
- **FR-024**: 自动化组件测试 MUST 覆盖中文文案、术语一致性、主题初始选择、手动切换、持久化、系统偏好变化、无存储回退、键盘、焦点、减少动态效果以及主要图表和拓扑视觉语义。
- **FR-025**: 真实浏览器测试 MUST 在三种代表性视口和两种主题下覆盖导航、实验室、资源添加、拓扑、Inspector、任务、Console、Capture、Traffic Filter、模板与自动化页面，并验证主题切换不改变权威资源状态或当前会话。
- **FR-026**: 在 `10.72.1.7` 的目标验收 MUST 至少验证一个运行中的 QEMU 节点、一个 Docker 节点、一条链路、一个 Console 会话和一个 Traffic Filter 会话在主题切换前后持续存在且可操作。

### Key Entities

- **界面语言资源**: 产品自有文案的统一集合，按页面、组件、动作、状态和错误场景组织；不包含用户数据和设备原始输出。
- **主题偏好**: 当前浏览器选择的浅色、深色或跟随设备状态，以及该选择是否由用户明确设置。
- **主题语义**: 背景、表面、文字、边框、焦点、状态、拓扑和图表所使用的用途定义，确保两种主题表达相同含义。
- **术语表**: 核心产品概念的标准中文名称及允许保留的英文缩写，用于防止页面间译法不一致。

## Assumptions

- 本次只提供简体中文产品界面，不引入多语言选择器；未来增加其他语言时应复用统一文案资源。
- “全页面中文化”指产品可控制的文案；设备系统、终端输出、远程桌面、用户输入和第三方专有名称保持原文。
- 主题提供浅色、深色和首次自动跟随设备偏好的行为；用户主动选择后以其选择为准。
- 语言固定为简体中文，主题偏好属于浏览器本地显示状态，不属于实验室共享状态。
- 本功能不改变任何后端资源、运行时适配器、数据库实体或自动化合同。

## Delivery and Deployment Constraints *(mandatory)*

- **Local milestone**: 至少按“中文化基础与术语”“全局主题与核心组件”“拓扑/图表/诊断适配”“全页面验收”划分可独立验证的本地里程碑，并分别通过格式、静态检查、单元、可访问性和浏览器测试。
- **Commit evidence**: 每个里程碑使用聚焦 Git 提交记录，最终验收文档必须列出提交 SHA、覆盖页面和测试结果。
- **Deployment artifact**: 从已识别的干净提交构建可复现候选产物，记录版本、候选标识、源提交、产物摘要、构建时间和迁移状态。
- **Target validation**: 使用正式安装流程部署到 `10.72.1.7`，在真实浏览器、两种主题和代表性运行资源上验证中文化、主题持久化、会话连续性和资源状态不变。
- **Rollback**: 保存部署前候选标识与产物摘要；验收失败时恢复上一已记录产物，并验证页面、已有实验室和运行会话恢复。
- **Target immutability**: Source fixes MUST NOT be made directly on `10.72.1.7`; failed validation returns to the local worktree for tests, a new commit, and redeployment.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 产品可控制的用户可见文案中，至少 99% 使用简体中文；剩余内容必须属于已声明保留原文的技术数据或第三方名称。
- **SC-002**: 用户可以在任意主要页面于 2 次操作内完成浅色与深色主题切换，切换结果在 300 毫秒内覆盖当前可见界面且无需刷新。
- **SC-003**: 在 1024×768、1366×768 和 1920×1080 三种视口下，两种主题均可完成全部关键用户流程，不出现阻塞性重叠、裁切或不可点击控件。
- **SC-004**: 浅色和深色主题下，所有关键文字、交互控件、焦点和状态标识均通过自动与人工可访问性检查；不得存在阻止任务完成的对比度问题。
- **SC-005**: 主题切换前后，当前实验室、节点、链路、选中对象、拓扑视口、未提交表单、Console/VNC/Capture/Traffic Filter 会话和运行任务保持不变，验收场景通过率为 100%。
- **SC-006**: 用户明确选择主题后，刷新页面、重新打开浏览器和切换实验室的主题保持成功率为 100%；不同浏览器主题隔离成功率为 100%。
- **SC-007**: 首次访问且未保存偏好时，系统跟随设备主题的自动判断在受支持浏览器中的正确率为 100%，且页面无明显错误主题闪烁。
- **SC-008**: 中文术语检查不发现核心概念的冲突译法，高风险操作均包含明确对象、动作和影响说明。
- **SC-009**: 在目标机代表性验收中，用户可在两种主题下完成添加资源、连接链路、启动节点、打开 Console、查看任务、抓包和 Traffic Filter 操作，且无需依赖英文界面说明。
