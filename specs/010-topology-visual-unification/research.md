# Research: 拓扑连接视觉与资源放置统一

## 1. 保留三类持久化连接，新增统一展示投影

**Decision**: 保留 `Link`、`NetworkAttachment`、`NetworkObjectLink` 的领域和运行时模型，在查询结果进入画布前转换为统一的 `ConnectionPresentation`。

**Rationale**: 三类连接对应不同资源所有权和 reconciliation 路径，但用户判断状态、选择线路、查看端点、抓包和 Traffic Filter 时需要一致语义。展示投影可以统一 ID、端点、实际状态、能力、平行分组和语义标记，而不承担高风险数据库迁移。

**Alternatives considered**:

- 合并为一张通用连接表：拒绝；会扩大迁移、恢复和运行时回归范围，且不能直接改善视觉体验。
- 在 `TopologyCanvas.vue` 继续分别拼三类边：拒绝；现有重复 curveness、标签和状态判断会持续漂移。
- 仅以 CSS 覆盖线条：拒绝；无法统一选择、可访问名称、能力和 Traffic Filter 归属。

## 2. 采用“状态优先、语义次之、交互覆盖”的视觉层级

**Decision**: 视觉优先级固定为：实际状态基础样式 → 连接语义标记 → 选中/键盘焦点 → 抓包和 Traffic Filter 临时覆盖。

**Rationale**: 颜色首先回答“是否正常”，不能同时被用来表示“是什么连接”。NAT、Bridge 等差异通过端点徽标、短标签或辅助线纹表达；选中和流量效果不得改写失败或处理中状态。

**Alternatives considered**:

- 按连接类型分配成功颜色：拒绝；会让用户误把蓝色、绿色、橙色理解为不同健康状态。
- Traffic Filter 直接替换基础边：拒绝；活动结束后容易残留错误状态，且会遮蔽失败线型。
- 只依赖颜色：拒绝；不满足浅色/深色、色觉差异和屏幕阅读要求。

## 3. 仅保留真实拓扑语义差异

**Decision**: 默认点到点连接不额外标记；NAT 管理上联使用 `managed-nat-uplink` 标记；共享 Bridge/交换域连接在确需解释多接入语义时使用 `shared-broadcast-domain` 标记；其他差异须有明确运行时含义和中文说明才能加入。

**Rationale**: 用户要求统一，而不是把每个持久化类型暴露为不同视觉。标记描述网络含义，不描述内部数据库表。

**Alternatives considered**:

- 为 `Link`、`Attachment`、`ObjectLink` 各建图例：拒绝；这是实现细节，不是用户心智模型。
- NAT 使用独立成功颜色：拒绝；破坏状态颜色一致性。
- 永久展示全部可能图例：拒绝；增加无关认知负担。

## 4. 动态图例由当前投影派生

**Decision**: 左下角图例分为基础状态和“当前拓扑特殊语义”；语义项只在至少一条当前连接使用该标记时出现，并列出中文名称、原因和可聚焦的连接数量。

**Rationale**: 图例必须解释屏幕上真实存在的差异，并能帮助定位，不应成为静态产品说明书。

**Alternatives considered**:

- 将图例配置持久化到实验室：拒绝；图例是连接快照的确定性派生结果。
- 在每条线上长期显示完整文字：拒绝；会与端口、节点名和平行线重叠。

## 5. 跨持久化类型统一平行连接分组

**Decision**: 使用无方向的规范端点对形成 `route_group_key`，再按稳定连接键排序并分配对称曲率；三类连接共享同一算法。

**Rationale**: 目前节点直连和对象直连使用不同曲率函数，跨类型或多接口场景容易重合。统一分组能在 50%、100%、200% 缩放下保持每条线路可见和可选。

**Alternatives considered**:

- 只按连接 ID 偏移：拒绝；不同刷新顺序可能改变路径。
- 让 ECharts force layout 自动分离：拒绝；会导致节点漂移并改变已有坐标。
- 随机曲率：拒绝；不可复现且不利于多客户端一致。

## 6. 位置分配必须是服务器权威创建工作流的一部分

**Decision**: 节点和网络对象创建请求接受可选 `placement_intent`；应用命令在同一事务中创建资源、分配位置、更新实验室 revision 并写 outbox，响应返回最终 `TopologyPlacement`。

**Rationale**: 当前客户端在创建成功后以画布中心补写位置，两个浏览器、API 或 MCP 并发时会选择相同坐标，也会出现资源已创建但 placement 失败的中间状态。原子工作流消除重叠和幽灵位置。

**Alternatives considered**:

- 继续客户端碰撞检测：拒绝；客户端看不到尚未同步的并发创建，也无法覆盖 API/MCP。
- 创建后调用独立 claim API：仅作为兼容备选；两步之间仍存在无位置窗口，必须增加预留和补偿复杂度。
- 自动移动已有资源腾位置：拒绝；违反已有坐标保持要求。

## 7. 使用规范化世界坐标足迹而非浏览器测量

**Decision**: 服务端维护少量版本化 `footprint_class`，每类定义主体宽高、标签/端口/加号余量和最小间距；客户端请求可声明支持的 class，但不能提交任意尺寸绕过规则。

**Rationale**: DOM/SVG 像素受主题、字体、缩放和客户端影响，不能作为共享事务判断依据。规范足迹保守覆盖标准标签密度下的完整可交互边界，并可通过合同版本演进。

**Alternatives considered**:

- 上传浏览器测量矩形：拒绝；不可信、不可复现且 API/MCP 无浏览器。
- 所有资源使用单点间距：拒绝；无法保护名称、端口和连接加号。
- 每模板保存任意像素尺寸：拒绝；把展示实现泄漏到领域模型并增加迁移成本。

## 8. 使用确定性最近槽位搜索

**Decision**: 从请求中心开始，在固定网格上按方形螺旋/逐环顺序检查候选矩形，选择第一个不与已提交 placement 足迹相交的位置；候选排序、步长、边界和最大搜索数固定并测试。

**Rationale**: 结果靠近用户当前视口、可重放、可测试；SQLite 写事务串行化并发创建，使每个提交看到前一个已占位置。

**Alternatives considered**:

- 随机撒点：拒绝；不可复现，可能远离视口且难以测试。
- 全局力导向布局：拒绝；改变旧坐标并产生视觉漂移。
- 无限搜索：拒绝；缺少明确超时和错误语义。

## 9. 位置调整透明但不要求用户确认

**Decision**: 响应提供 `requested_center`、`assigned_center`、`adjusted` 和 `reason`；若请求位置冲突则自动选择最近安全位置并成功返回，只有超出边界或候选耗尽才返回结构化错误。

**Rationale**: 添加资源的主目标是快速可用，普通碰撞不应变成阻断式弹窗；调整元数据可供 UI 提示、审计和自动化验证。

**Alternatives considered**:

- 每次调整都要求确认：拒绝；打断连续创建。
- 静默调整且不返回信息：拒绝；API/MCP 无法解释最终位置。

## 10. 兼容已有 placement 移动接口

**Decision**: 保留 `PUT /api/v1/labs/{labId}/placements` 用于拖动和多选移动；本功能只加强新建时的权威初始位置。既有 placement 不进行启动时重算。

**Rationale**: 手工拖动与首次放置是不同命令。保留接口减少回归面，并确保升级后旧实验室坐标变化为零。

**Alternatives considered**:

- 所有移动都走 placement claim：拒绝；会改变现有多选拖动和 optimistic UI 语义。
- 升级时批量修复重叠：拒绝；不符合显式保持坐标要求。

## 11. 前端预测只用于体验，返回位置覆盖预测

**Decision**: 客户端可用当前画布中心形成 intent 和临时占位，但必须以创建响应或有序事件中的权威 placement 覆盖；若最终位置不在视口内，提供一键定位而不平移整个图。

**Rationale**: 保持即时反馈，同时避免客户端成为坐标事实来源。节点位置变化只更新新资源，不触发 ECharts 自动布局或旧节点回弹。

**Alternatives considered**:

- 等待完整实验室刷新后再显示：拒绝；降低反馈速度。
- 让客户端结果覆盖服务器：拒绝；破坏共享状态和并发一致。

## 12. 主题、可访问性和性能策略

**Decision**: 状态使用主题语义变量，并同时编码在线型、宽度、端点/标记和文本；图例与连接提供可访问名称；连接投影和 route group 使用 memoized/computed 派生，不启用 force layout，不因 Traffic Filter observations 重新计算节点位置。

**Rationale**: 统一视觉必须在浅色/深色和键盘下成立，也必须解决历史上的漂移、收缩和覆盖层残留。

**Alternatives considered**:

- 每帧重建完整 graph option：拒绝；会造成位置漂移和大拓扑卡顿。
- 用动画粒子承担全部方向表达：拒绝；静止、低帧率和辅助技术下不可辨识。

## 13. 部署与回滚

**Decision**: 按四个里程碑在本地提交，构建可复现候选并记录 SHA/摘要后部署 `10.72.1.7`；目标机失败返回本地修复并生成新提交，回滚到上一已验证制品。

**Rationale**: 宪法要求目标环境用于验收而非源码开发；连接视觉和 placement 变更涉及共享状态，必须保留可追溯恢复点。

**Alternatives considered**:

- 直接在目标机热改前端：拒绝；不可追溯且无法稳定回滚。
- 单个大提交：拒绝；无法隔离视觉、图例、placement 和恢复问题。
