# Feature Specification: 拓扑连接视觉统一与自动避让

**Feature Branch**: `[010-topology-visual-unification]`

**Created**: 2026-08-07

**Status**: Draft

**Input**: User description: "包括网桥、交换机、节点之间的连接都进行统一；节点与节点之间的线路样式和状态也统一优化；确有必要保留差异的连接类型，例如 NAT 网桥连接，应在拓扑图左下角增加样式标注并说明原因；创建新节点或网络对象时不得与已有资源重叠，避免用户创建后还要额外拖动。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一眼识别所有连接的状态 (Priority: P1)

作为网络实验用户，我希望节点、网桥、NAT、PC、轻量 L2 和轻量 L3 之间的连接使用统一的状态语言和视觉层级，使我只需学习一次就能识别待处理、正常、失败、断开中、被选中和正在承载匹配流量等状态。

**Why this priority**: 当前不同连接资源采用不同颜色、线型和状态名称，容易让用户把底层实现差异误认为网络状态差异，增加故障判断成本。

**Independent Test**: 在同一实验室内建立节点到节点、节点到 Bridge、节点到 NAT、节点到轻量交换机以及轻量对象间连接，依次制造待处理、成功、失败、断开中、选中和 Traffic Filter 活动状态，确认所有连接遵循同一套状态规则。

**Acceptance Scenarios**:

1. **Given** 不同资源类型之间存在多种连接，**When** 它们均处于正常连接状态，**Then** 所有连接使用相同的基础“正常”视觉语义，不因底层连接类别改变状态颜色。
2. **Given** 任意连接进入待处理、失败或断开处理中，**When** 用户查看拓扑，**Then** 该连接使用与其他连接类别一致的对应状态样式和中文状态说明。
3. **Given** 用户选中一条连接，**When** 该连接同时具有正常、失败或流量活动状态，**Then** 选择强调不会覆盖或混淆其基础状态。
4. **Given** Traffic Filter 命中某条连接，**When** 匹配流量出现和停止，**Then** 流量粒子或方向提示叠加在统一基础线条上，并在衰减后恢复原连接状态样式。
5. **Given** 两个资源之间存在多条平行连接，**When** 用户查看或选择其中一条，**Then** 各连接保持独立路径、端口标签、点击区域和状态，不会视觉重合为一条线。

### User Story 2 - 理解确有必要的连接差异 (Priority: P1)

作为首次使用系统的用户，当某类连接必须因为网络语义而使用不同标记时，我可以在拓扑左下角直接看到当前出现的线条或标记含义及其原因，而不需要猜测颜色、虚线或图标代表什么。

**Why this priority**: 完全抹平 NAT、逻辑接入或特殊转发关系可能造成误导；保留差异时必须提供就地解释，不能让用户自行推断。

**Independent Test**: 创建包含普通点到点连接、共享 Bridge 接入、NAT 接入和对象间直连的拓扑，确认只有存在真实语义差异的连接才显示补充标记，左下角图例只列出当前实际出现的样式并提供中文原因说明。

**Acceptance Scenarios**:

1. **Given** 当前拓扑中的连接没有需要额外说明的语义差异，**When** 用户查看左下角图例，**Then** 图例保持简洁，不重复展示所有普通连接类型。
2. **Given** 当前拓扑存在 NAT 接入或其他必须区分的连接，**When** 系统使用特殊线型、端点标记或徽标，**Then** 左下角图例同步展示示例、名称和采用差异的原因。
3. **Given** 特殊连接的状态从正常变为失败，**When** 用户查看拓扑，**Then** 统一状态样式优先表达失败，特殊类型标记仍可识别但不得覆盖失败信息。
4. **Given** 用户悬停或聚焦图例项目，**When** 当前拓扑中存在对应连接，**Then** 相关连接得到非破坏性强调，其他连接仍保持可见。
5. **Given** 用户使用浅色、深色或高对比环境，**When** 查看图例和连接，**Then** 不依赖单一颜色即可区分状态和必要类型差异。

### User Story 3 - 新资源创建后自动落在空白位置 (Priority: P1)

作为编辑拓扑的用户，我希望新建 QEMU、Docker、PC、Bridge、NAT、轻量 L2 或轻量 L3 后，资源自动出现在当前画布附近的可用空白位置，不覆盖已有节点、标签、端口或其他刚创建的资源。

**Why this priority**: 新资源重叠会让用户误以为创建失败或资源丢失，并迫使用户立即拖动整理，显著打断连续搭建拓扑的流程。

**Independent Test**: 在画布中心和四周已有多个资源的实验室中连续创建至少 20 个不同类型资源，确认每个新资源都能直接看见、可选择，并与已有资源保持规定间距，无需手工移动才能识别。

**Acceptance Scenarios**:

1. **Given** 当前视口中心位置为空，**When** 用户创建一个新资源，**Then** 新资源出现在视口中心附近且不与现有资源重叠。
2. **Given** 首选位置已被资源、可见标签或端口占用，**When** 创建新资源，**Then** 系统选择距离首选位置最近的安全空位，而不移动已有资源。
3. **Given** 用户连续创建多个资源，**When** 每次创建完成，**Then** 新资源按可预测顺序分布在相邻空位，不堆叠在同一点。
4. **Given** 两个客户端几乎同时创建资源，**When** 权威拓扑状态提交完成，**Then** 两个资源获得不同的共享位置，所有客户端看到相同结果。
5. **Given** 当前视口已经非常拥挤，**When** 没有满足首选间距的空位，**Then** 系统在最近的可扩展区域放置资源并确保其可发现，而不是覆盖已有资源。

---

### User Story 4 - 保持旧实验室稳定并支持一致控制面 (Priority: P2)

作为已有实验室的维护者，我希望升级后旧连接自动采用新的统一视觉规则，但原有拓扑坐标、端点、运行状态和网络行为不被擅自修改；通过浏览器、自动化接口或 MCP 创建的新资源都遵循相同的非重叠放置规则。

**Why this priority**: 视觉统一和自动布局不能以破坏已整理好的实验室或造成多客户端位置漂移为代价。

**Independent Test**: 加载一个包含手工布局、平行连接、失败连接和运行中节点的旧实验室，通过不同控制面分别新增资源并重启服务，确认原资源不移动、新资源不重叠、连接状态与样式一致恢复。

**Acceptance Scenarios**:

1. **Given** 一个已有实验室包含手工保存的位置，**When** 系统升级并重新打开实验室，**Then** 原有资源坐标保持不变，仅连接视觉规则更新。
2. **Given** 新资源由浏览器以外的控制面创建且未指定位置，**When** 创建提交，**Then** 系统为其分配共享的非重叠位置。
3. **Given** 创建方明确提交合法位置，**When** 该位置不会与已有资源重叠，**Then** 系统尊重该位置；存在冲突时返回调整后的权威位置或明确冲突结果。
4. **Given** 服务在新资源位置提交后重启，**When** 实验室恢复，**Then** 新位置、连接状态和必要图例分类保持一致。

### Edge Cases

- 连接同时处于失败、被选中和 Traffic Filter 活跃状态时，各视觉层必须有明确优先级，不能用一个效果覆盖全部含义。
- 两条或更多平行连接端点相同但端口不同，自动曲线分离后不得穿过节点主体、端口标签或右上角连接加号。
- 连接非常短、节点距离很近或缩放比例很小时，状态线型、端点和点击区域仍需可辨认且不会遮挡节点名称。
- NAT、Bridge 或共享二层接入在底层不是普通点到点链路时，视觉差异只能表达真实拓扑语义，不能仅因为内部数据类别不同而产生不同颜色。
- 左下角同时存在资源类型图例、Traffic Filter 图例和连接样式图例时，必须避免重叠、重复和超出视口，并允许折叠或按当前上下文精简。
- 图例项目对应的连接全部被删除后，该项目应实时消失，不得要求刷新页面。
- 新资源的候选位置与折叠检查器、底部面板、画布工具栏或图例重叠时，应以实际可操作画布区域计算放置位置。
- 新资源图标不重叠但名称、端口、加号或状态标签发生重叠时，也视为放置冲突。
- 在极度密集拓扑中无法满足理想间距时，应优先保证资源主体不重叠和可选择，并提供可发现位置；不得自动重排或移动已有资源。
- 导入的旧实验室本身已经存在重叠时，本功能不自动改写旧坐标；只有新创建资源必须避开当前可见占用范围。
- 创建任务失败或被取消时，不得保留仅用于占位的幽灵资源或永久空洞；后续创建可以重新使用该空间。
- 多客户端同时创建、移动和删除资源时，位置冲突应由权威状态裁决，客户端预测位置必须以最终共享位置为准。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 为节点到节点、节点到 Bridge、节点到 NAT、节点到轻量网络对象、轻量对象到轻量对象等连接提供统一的基础线条、状态名称和交互反馈。
- **FR-002**: 连接的基础颜色和线型 MUST 优先表达实际状态，而不是底层连接存储类别或运行时实现方式。
- **FR-003**: 所有连接 MUST 使用一致的实际状态集合，至少包括“待处理”“已连接”“失败”和“断开处理中”，并在检查器、任务反馈和拓扑中使用一致中文名称。
- **FR-004**: 合法状态转换 MUST 包括待处理到已连接或失败、失败重试到待处理、已连接到断开处理中，以及断开处理中到删除完成或明确失败。
- **FR-005**: 已连接状态 MUST 使用稳定、低干扰的基础样式；待处理、失败和断开处理中 MUST 分别具有不依赖单一颜色的可辨识线型或标记。
- **FR-006**: 连接被选中、悬停、键盘聚焦或作为当前检查对象时，系统 MUST 使用独立强调层，不得覆盖连接实际状态。
- **FR-007**: Traffic Filter、抓包活动和方向提示 MUST 作为临时观察层叠加在基础连接上，并在活动结束后恢复基础状态，不得永久改变连接样式。
- **FR-008**: 多条平行连接 MUST 根据具体端点对自动分离路径，并保持独立标签、选择区域、状态、抓包和 Traffic Filter 归属。
- **FR-009**: 连接标签 MUST 优先使用人类可读的 `资源名:端口 ↔ 资源名:端口`；Bridge 或 NAT 没有固定端口名称时 MUST 使用清晰的逻辑接入口名称。
- **FR-010**: 系统 MUST 仅在真实网络语义需要区分时使用特殊类型标记；不得仅因为连接由不同内部模型保存而使用不同基础状态颜色。
- **FR-011**: 使用特殊线型、端点符号或徽标的连接 MUST 在拓扑左下角图例中展示同样示例、中文名称和差异原因。
- **FR-012**: 连接样式图例 MUST 根据当前实验室实际存在的连接动态生成；不存在对应连接时 MUST 隐藏该图例项。
- **FR-013**: 图例 MUST 明确区分“连接状态”和“连接语义”，避免用户将 NAT、共享网段或对象直连标记误认为成功或失败状态。
- **FR-014**: 图例 MUST 支持浅色、深色、键盘操作和非颜色识别，并且在缩小视口或存在其他左下角图例时保持不重叠、可滚动或可折叠。
- **FR-015**: 用户聚焦或悬停图例项时，系统 SHOULD 临时强调对应连接；该操作不得改变共享拓扑状态。
- **FR-016**: 新创建的 QEMU、Docker、PC、Bridge、NAT、轻量 L2 和轻量 L3 MUST 获得一个不与已有资源可视边界重叠的初始共享位置。
- **FR-017**: 放置冲突检测 MUST 考虑资源主体、可见名称、端口、连接加号和必要状态标签，而不只考虑图标中心点。
- **FR-018**: 新资源首选位置 MUST 位于当前用户创建上下文附近；首选位置被占用时 MUST 选择距离最近且满足安全间距的候选位置。
- **FR-019**: 自动放置 MUST NOT 移动、重排或改写已有资源的位置，包括已有资源本身已经重叠的旧实验室。
- **FR-020**: 连续创建多个资源 MUST 使用可预测且稳定的扩展顺序，避免所有资源落在相同中心点或沿单一方向无限堆积。
- **FR-021**: 自动放置 MUST 以当前可操作画布区域为边界，避开工具栏、检查器、底部面板、连接图例和其他遮挡区域。
- **FR-022**: 当首选区域无法容纳新资源时，系统 MUST 扩展到最近的可发现区域，并向当前客户端保证新资源创建后可见或提供立即定位入口。
- **FR-023**: 多客户端并发创建资源时，系统 MUST 以权威顺序分配不同位置；客户端预测与最终位置不同的，必须平滑收敛到权威位置而不产生重复资源。
- **FR-024**: 浏览器、HTTP 控制面和适用的 MCP 工具创建资源时 MUST 遵循相同的位置规则；未明确指定位置的创建请求必须获得共享位置。
- **FR-025**: 明确指定的位置只有在合法、有限且不与已有资源冲突时才能直接采用；冲突处理结果 MUST 对调用方可见且可审计。
- **FR-026**: 资源创建、位置分配和连接状态变更 MUST 支持幂等请求；重复请求不得创建额外资源、重复位置或重复连接视觉记录。
- **FR-027**: 创建任务超时、取消或部分失败时，系统 MUST 清理未提交资源和临时位置占用；已提交资源的位置必须能够通过查询确认。
- **FR-028**: 服务启动、实验室恢复和客户端重新连接后，系统 MUST 使用持久化的共享位置和权威连接状态重建拓扑视觉，不得因客户端不同产生新的自动布局。
- **FR-029**: 删除资源或连接后，相关线条、图例项、位置占用和选择状态 MUST 从所有客户端及时消失；释放的位置可被后续新资源使用。
- **FR-030**: 连接创建、删除和状态变化 MUST 继续支持实时抓包、Wireshark 流、Traffic Filter、保留期限、大小限制、完成原因和截断状态；视觉统一不得改变观察制品语义。
- **FR-031**: 系统 MUST 记录资源创建入口、请求位置、最终位置、冲突调整、连接状态变化和图例分类依据，以支持审计和故障诊断。
- **FR-032**: 本功能 MUST 遵守现有资源数量、接口数量、任务并发和宿主机容量限制，不得通过自动放置或视觉统一扩大运行时权限。
- **FR-033**: 已有实验室的资源位置、连接端点、网络配置和运行状态 MUST 保持兼容；升级只改变统一视觉表达，不自动迁移或重排旧坐标。
- **FR-034**: 连接视觉与自动放置 MUST 可通过键盘和辅助技术感知；线条状态、图例说明和新资源位置不得只通过颜色或指针悬停传达。

### Key Entities

- **Connection Visual State**: 用户看到的连接基础状态，包含统一状态名称、线型、颜色、端点标记、选择层和临时观察层。
- **Connection Semantic Marker**: 仅在真实网络语义存在差异时使用的补充标记，例如 NAT 接入、共享网段接入或对象间直连；不承担成功或失败状态表达。
- **Topology Legend Item**: 当前实验室中实际出现的状态或语义样式说明，包含视觉示例、中文名称、原因和对应连接集合。
- **Visual Bounds**: 一个资源在当前标签密度和缩放策略下占用的可交互边界，包括图标、名称、端口、加号和必要状态文本。
- **Placement Candidate**: 新资源可选择的候选位置，包含与创建上下文的距离、碰撞结果、可见性和排序优先级。
- **Authoritative Placement**: 与实验室共享并持久化的最终资源位置，所有客户端和控制面以此为准。

## Assumptions

- 本功能依赖 `specs/009-unified-link-interaction/spec.md` 定义的统一端点选择和连接创建体验；本规格负责连接视觉、状态表达、图例和新资源放置。
- 所有连接共享同一套基础状态样式；NAT、Bridge 或对象直连如需区分，优先使用轻量端点徽标或辅助线型，而不是改变成功、失败状态颜色。
- 新资源的创建上下文默认为当前画布中心或用户选择的确认位置附近；自动避让结果属于共享实验室状态。
- “不重叠”以当前标准标签密度下资源的完整可视边界为准，并保留足够选择间距；在极密拓扑中可以降低理想间距，但资源主体不得重叠。
- 已有重叠布局不自动修复；未来如需全局自动整理，应作为独立功能提供并由用户显式触发。

## Out of Scope

- 自动重排整个已有实验室或强制修复导入拓扑中的旧重叠。
- 使用线条样式替代检查器、诊断、任务错误或实际状态详情。
- 根据连接类型自动更改 VLAN、路由、NAT 或转发配置。
- 在不同实验室之间共享坐标、布局或图例状态。
- 引入多节点集群布局协调。

## Delivery and Deployment Constraints *(mandatory)*

- **Local milestone**: 按“统一连接状态样式”“语义差异与动态图例”“新资源碰撞避让”“并发与恢复验收”拆分本地里程碑；每个里程碑通过相应视觉、交互、契约、状态同步和回归测试后才能完成。
- **Commit evidence**: 每个本地里程碑必须形成独立 Git 提交并记录提交 SHA、测试命令和结果；部署制品只能来自干净且已验证的提交。
- **Deployment artifact**: 从已记录提交构建可复现制品，记录制品摘要、候选标识、构建时间和契约版本。
- **Target validation**: 在 `10.72.1.7` 创建同时包含 QEMU、Docker、PC、Bridge、NAT、轻量 L2 和轻量 L3 的实验室，验证全部连接状态、平行线路、图例、浅色/深色主题、连续创建 20 个资源、双客户端并发创建、服务重启恢复和实验室删除清理。
- **Rollback**: 部署前保存上一已验证制品和配置；若连接状态误导、旧拓扑坐标变化、资源重叠、共享位置不一致或清理失败，恢复上一制品并确认既有实验室正常。
- **Target immutability**: Source fixes MUST NOT be made directly on `10.72.1.7`; failed validation returns to the local worktree for tests, a new commit, and redeployment.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户在不打开检查器的情况下，能够在 3 秒内正确判断任意受支持连接处于待处理、已连接、失败还是断开处理中。
- **SC-002**: 节点到节点、节点到 Bridge、节点到 NAT、节点到轻量对象和轻量对象间连接在相同状态下使用一致的基础状态视觉，人工验收一致率达到 100%。
- **SC-003**: 所有采用特殊类型标记的连接都能在左下角找到对应中文说明和差异原因，未说明的特殊样式数量为 0。
- **SC-004**: 浅色和深色主题下，连接状态和语义差异均无需仅凭颜色即可识别，键盘聚焦和屏幕阅读说明覆盖全部图例项。
- **SC-005**: 至少三条平行连接在 50%、100% 和 200% 缩放下保持独立可见、可选择和可归属观察，错误选中率为 0。
- **SC-006**: 连续创建 20 个混合类型资源时，资源主体、名称、端口和连接加号之间不发生初始重叠，用户无需为了识别新资源进行手工拖动。
- **SC-007**: 两个客户端并发创建 10 组资源时，每组资源获得不同权威位置，所有客户端在 2 秒内收敛到相同布局。
- **SC-008**: 新资源从创建成功到在当前画布中可见或可一键定位的时间不超过 2 秒。
- **SC-009**: 升级并恢复三个既有实验室后，原有资源坐标、端点关系和网络配置变化数量为 0。
- **SC-010**: 在 20 次创建失败、取消、删除和重新创建循环中，不出现幽灵资源、永久占位、重复图例项或不可复用位置。
- **SC-011**: Traffic Filter 活动停止并经过既定衰减时间后，100% 的连接恢复到正确基础状态样式，不持续显示过期流量效果。
- **SC-012**: 服务重启后连接视觉、图例分类和共享位置全部恢复；删除测试实验室后相关位置、连接和运行时资源清理率达到 100%。
