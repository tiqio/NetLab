# Feature Specification: 统一拓扑端口连接体验

**Feature Branch**: `[009-unified-link-interaction]`

**Created**: 2026-08-07

**Status**: Draft

**Input**: User description: "统一接口连接方式，使连接更加方便；轻量级二层和轻量级三层设备默认创建四个端口；连接既可以通过设备右上角的加号开始，也可以直接从接口拖到目标接口或目标设备。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从任意端口直接拖拽连接 (Priority: P1)

作为网络实验用户，我可以从 QEMU、Docker、PC、轻量级二层交换机或轻量级三层设备的任意空闲端口开始拖拽，将连线放到另一个兼容端口或目标设备上，而不需要先判断这次连接属于普通链路、网络附件还是网络对象间链路。

**Why this priority**: 端口连接是拓扑编辑中最频繁的操作。统一拖拽行为能够消除不同设备类型之间的操作差异，直接降低误操作和学习成本。

**Independent Test**: 在一个包含 QEMU、Docker、PC、轻量 L2、轻量 L3、Bridge 和 NAT 的实验室中，分别完成节点到节点、节点到轻量对象、轻量对象到轻量对象以及节点到 NAT/Bridge 的拖拽连接，并确认每次连接都形成可选择、可观察、可实时删除的拓扑资源。

**Acceptance Scenarios**:

1. **Given** 两个普通虚拟节点各有至少一个空闲接口，**When** 用户从源接口拖到目标接口，**Then** 系统创建对应连接并在画布上展示连接状态。
2. **Given** 一个普通节点接口和一个轻量网络对象端口均空闲，**When** 用户直接在画布上完成拖拽，**Then** 系统创建连接，不再要求用户转到检查器执行附件操作。
3. **Given** 两个轻量网络对象各有空闲端口，**When** 用户从一个对象端口拖到另一个对象端口，**Then** 系统创建可独立选择、抓包、流量过滤和删除的对象间连接。
4. **Given** 用户将连线放到一个拥有多个空闲端口的目标设备主体上，**When** 系统无法唯一确定目标端口，**Then** 用户可以在紧邻操作位置的端口选择界面中完成选择，而不丢失当前连线上下文。
5. **Given** 用户正在拖拽连线，**When** 指针经过可连接、已占用或不兼容的目标，**Then** 目标分别显示明确的可连接、不可用或不兼容反馈。

---

### User Story 2 - 使用统一加号快速连接 (Priority: P1)

作为偏好点击操作的用户，我可以使用设备右上角的加号开始连接。加号在普通节点和轻量网络对象上的行为一致，系统帮助我选择源端口，再使用与拖拽方式相同的目标选择和连接流程。

**Why this priority**: 加号入口已经形成用户习惯，不能因为引入拖拽连接而被移除；同时它必须适用于所有设备类型，避免再次形成两套操作规则。

**Independent Test**: 对普通节点、轻量 L2 和轻量 L3 分别点击加号，选择源端口并连接到普通节点、轻量对象和 NAT，确认后续步骤、状态反馈和最终结果与直接拖拽方式一致。

**Acceptance Scenarios**:

1. **Given** 任意具有空闲端口或接入能力的拓扑资源被选中，**When** 用户点击其右上角加号，**Then** 系统开始统一连接流程并突出显示可用目标。
2. **Given** 源设备只有一个空闲端口，**When** 用户点击加号，**Then** 系统自动选中该端口并进入目标选择状态。
3. **Given** 源设备有多个空闲端口，**When** 用户点击加号，**Then** 系统要求用户选择源端口，并在选择后继续同一个连接流程。
4. **Given** 连接流程由加号启动，**When** 用户按 Escape、点击空白区域或再次点击同一源端口，**Then** 系统取消临时连线且不产生任何拓扑变更。

---

### User Story 3 - 创建默认四端口轻量交换设备 (Priority: P1)

作为搭建多跳拓扑的用户，我在新建轻量级二层或三层设备时默认获得四个可见、可独立配置和连接的端口，不必在每次创建后手工逐个增加端口。

**Why this priority**: 单端口轻量设备无法直接满足常见汇聚、双上联或多跳实验，导致创建后的第一步通常是重复扩口。

**Independent Test**: 分别新建一个轻量 L2 和一个轻量 L3，确认两者默认显示 `eth0`、`eth1`、`eth2`、`eth3`，四个端口均可用于连接，且各端口配置互不覆盖。

**Acceptance Scenarios**:

1. **Given** 用户选择创建轻量 L2，**When** 打开默认配置，**Then** 配置中包含四个名称唯一的端口 `eth0` 至 `eth3`，并保留默认二层转发和 VLAN 行为。
2. **Given** 用户选择创建轻量 L3，**When** 打开默认配置，**Then** 配置中包含四个名称唯一的接口 `eth0` 至 `eth3`，每个接口可以独立配置地址。
3. **Given** 用户不修改默认端口配置并完成创建，**When** 设备出现在拓扑中，**Then** 四个端口均可被识别、选择和连接。
4. **Given** 已有轻量设备只配置了一个或少于四个端口，**When** 本功能上线或实验室恢复，**Then** 系统保留其原有端口配置，不自动增加端口或改变既有连接。

---

### User Story 4 - 实时、安全地完成统一连接 (Priority: P2)

作为正在运行实验的用户，我可以在节点和轻量设备保持运行的情况下使用统一连接方式增删连接，并获得一致的任务状态、失败原因和恢复结果。

**Why this priority**: 统一交互只有在实时接线、并发操作和失败恢复中保持可靠，才能替代现有多套入口。

**Independent Test**: 在多个资源保持运行且两个浏览器同时打开同一实验室时创建、冲突创建、取消和删除不同类型连接，确认权威状态一致、失败不产生幽灵连线、其他客户端及时更新。

**Acceptance Scenarios**:

1. **Given** 源端口和目标端口对应的资源正在运行，**When** 用户完成连接，**Then** 系统不要求停止资源，并展示从待处理到已连接或失败的实际状态。
2. **Given** 两个客户端同时尝试占用同一端口，**When** 一个连接先成功，**Then** 另一个客户端收到端口已占用提示并刷新为权威拓扑状态。
3. **Given** 连接运行时创建失败或部分资源已经产生，**When** 系统完成失败处理，**Then** 不留下错误占用、幽灵线条或无法复用的端口。
4. **Given** 一个连接已经建立，**When** 用户选择它进行抓包、Traffic Filter 或删除，**Then** 操作入口和反馈不因底层连接类别不同而改变。

### Edge Cases

- 用户从一个端口拖回同一端口、同一设备不允许自连的另一个端口，或者已连接端口时，系统不得提交无效变更。
- 用户拖拽到设备主体但目标没有空闲端口时，系统应明确说明无可用端口，并保持拓扑不变。
- 用户拖拽过程中缩放、平移、切换实验室、切换浏览器标签页或失去窗口焦点时，临时连接必须安全取消或保持在可恢复的明确状态，不能留下跨实验室预览线。
- 用户拖拽经过节点本身时，不得误触发节点移动、画布平移或缩放；端口拖拽、节点拖动和画布平移必须有明确手势边界。
- 目标为轻量 L2 且需要 PVID 或 Tagged VLAN 配置时，系统应在提交前提供配置步骤，并保留可直接接受默认值的快速路径。
- Bridge 或 NAT 没有固定命名端口列表时，设备主体仍应作为可识别的接入目标，并按照当前容量和冲突规则接受多个合法连接。
- 多条平行连接连接同一对设备时，每条连接必须保持独立端点标识、选择区域、状态和观察结果。
- 在连接提交后、实际生效前删除源资源、目标资源或端口时，连接应进入明确失败或取消状态，并清理已创建的部分资源。
- 端口名称或端口数量被用户修改后，画布、检查器、导入导出和自动化控制面应使用实际保存的配置，而不是继续假定默认四端口。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 为 QEMU、Docker、PC、轻量 L2、轻量 L3、Bridge 和 NAT 提供一致的连接概念与用户操作，不要求用户先识别底层连接类别。
- **FR-002**: 系统 MUST 在资源被选中、悬停或进入连接模式时展示其可操作端口；Bridge 和 NAT MUST 展示可识别的接入目标。
- **FR-003**: 用户 MUST 能够从任意空闲端口拖拽到兼容端口或目标资源主体来创建连接。
- **FR-004**: 拖拽连接 MUST 显示始终锚定源端口的预览线，并随指针移动；预览过程不得改变节点位置或画布缩放。
- **FR-005**: 所有具有空闲端口或接入能力的资源 MUST 提供位置一致的加号快捷入口。
- **FR-006**: 加号入口 MUST 与端口拖拽共享相同的源端点、目标端点、兼容性判断、配置确认、提交和失败反馈流程。
- **FR-007**: 当源资源只有一个空闲端口时，系统 MUST 自动选择该端口；存在多个空闲端口时，系统 MUST 允许用户明确选择源端口。
- **FR-008**: 当用户将连接放到资源主体且该资源有多个可用目标端口时，系统 MUST 要求用户选择目标端口；只有一个可用端口时 MUST 自动选择。
- **FR-009**: 普通节点接口与轻量网络对象之间 MUST 能够直接从画布连接，不得强制用户转到检查器完成独立的 Attachment 流程。
- **FR-010**: 系统 MUST 根据两个端点的资源类型创建正确的权威连接，同时向用户呈现统一的名称、期望状态、实际状态和错误信息。
- **FR-011**: 统一连接的期望状态 MUST 至少包含“已连接”和“已断开”；实际状态 MUST 至少区分“待处理”“已连接”“失败”和“断开处理中”。合法转换 MUST 包括待处理到已连接或失败、失败重试到待处理、已连接到断开处理中，以及断开处理中到删除完成或明确失败，且转换对所有控制面一致可见。
- **FR-012**: 连接创建和删除 MUST 支持资源运行期间实时执行，不得以停止节点或轻量网络对象作为常规前置条件。
- **FR-013**: 对需要二层端口参数的连接，系统 MUST 在提交前允许确认 PVID 和 Tagged VLAN；未修改时 MUST 使用清晰展示的默认值。
- **FR-014**: 新建轻量 L2 的默认配置 MUST 包含四个端口 `eth0`、`eth1`、`eth2`、`eth3`，名称唯一且均可独立连接和配置。
- **FR-015**: 新建轻量 L3 的默认配置 MUST 包含四个接口 `eth0`、`eth1`、`eth2`、`eth3`，名称唯一且均可独立配置地址、路由关联和连接。
- **FR-016**: 本功能 MUST NOT 自动修改已有轻量 L2/L3 的端口数量、名称、地址、VLAN 或既有连接。
- **FR-017**: 用户 MUST 能够在创建轻量设备前增加、删除、重命名或调整默认端口配置，只要最终配置合法且名称不重复。
- **FR-018**: 已占用、不存在、跨实验室或不兼容的端点 MUST 在提交前尽可能阻止，并在服务端再次验证。
- **FR-019**: 同一端口的并发连接请求 MUST 由权威状态串行裁决；失败客户端 MUST 收到可操作的冲突说明并同步最新拓扑。
- **FR-020**: 重复提交同一个连接请求 MUST 返回同一最终结果，不得创建重复连接；相同请求标识用于不同端点时 MUST 被拒绝。
- **FR-021**: 连接创建和删除 MUST 作为可跟踪操作展示排队、执行、成功、失败、取消和进度；超时或取消后 MUST 给出最终资源状态检查方式。
- **FR-022**: 创建失败、取消、资源删除、服务重启或主机恢复后，系统 MUST 对连接和端口占用进行协调，并清理归属于失败操作的接口、桥接关系、命名空间端点和保留记录。
- **FR-023**: 所有浏览器客户端 MUST 观察到一致的共享连接状态；某一客户端的临时拖拽、端口选择器和预览线 MUST 保持客户端本地隔离。
- **FR-024**: 图形界面、HTTP 控制面和适用的 MCP 工具 MUST 支持等价的端点表达、连接创建、查询、删除、幂等和错误语义。
- **FR-025**: 统一连接 MUST 继续支持选择、检查、实时抓包、Wireshark 流式访问、Traffic Filter 高亮、方向展示和实时删除，不得因统一入口丢失现有观察能力。
- **FR-026**: 多条平行连接 MUST 按具体端口对独立展示和观察，不能合并为一条无法区分的连接。
- **FR-027**: 系统 MUST 记录连接请求的发起入口、端点、配置、任务结果、冲突和清理结果，以便审计和诊断，但不得记录与连接无关的终端内容或抓包载荷。
- **FR-028**: 统一连接交互 MUST 可通过键盘完成，包括聚焦资源、选择源端口、选择目标、确认和取消，并提供可感知的状态说明。
- **FR-029**: 端口拖拽、节点拖动、框选和画布平移 MUST 使用互斥且可预测的手势判定；一次手势不得同时触发两个拓扑操作。
- **FR-030**: 系统 MUST 保持现有实验室导入导出、恢复策略和共享拓扑兼容性；旧连接在加载后应使用统一外观和操作入口，而不要求用户迁移实验室。
- **FR-031**: 连接创建 MUST 遵守资源声明的接口数量、端口占用、并发任务和宿主机容量限制；统一交互不得绕过现有权限边界、扩大运行时特权或自动创建超出资源配置的端口。
- **FR-032**: 通过统一连接发起的抓包 MUST 继续提供现有的实时流、保留制品、大小上限、保留期限、完成原因和截断状态；连接统一不得降低二进制制品的可追踪性。

### Key Entities

- **Connection Endpoint**: 用户可连接的端点，代表普通节点接口、轻量网络对象命名端口，或 Bridge/NAT 的逻辑接入口；包含所属资源、显示名称、可用性和兼容能力。
- **Topology Connection**: 用户视角中的统一连接资源，关联两个端点、连接配置、期望状态、实际状态、错误、版本和观察能力；其底层实现类别不影响主要操作方式。
- **Connection Draft**: 当前客户端尚未提交的临时连接，包含源端点、指针位置、候选目标、待确认端口和可选连接参数；不属于共享实验室状态。
- **Lightweight Port Set**: 轻量 L2/L3 保存的命名端口集合；新设备默认包含四个端口，已有设备保持原集合。
- **Connection Task**: 连接创建、删除、取消和恢复过程的可跟踪操作，包含幂等标识、进度、结果、错误和清理状态。

## Assumptions

- 新建轻量 L2/L3 默认使用现有命名习惯，生成 `eth0` 至 `eth3`，用户仍可在创建前修改。
- 默认四端口只影响新建资源；对既有资源自动扩口可能改变路由、VLAN 和端口占用，因此不在本功能范围内。
- Bridge 和 NAT 保持当前可多节点接入的语义，在画布上以逻辑接入口或设备主体作为拖放目标，不强制用户管理固定数量的命名端口。
- 加号是端口连接的快捷入口，而不是另一套独立连接功能；直接点击端口选择源和目标可作为拖拽的等价无障碍备用操作。
- 本功能不改变各类连接已有的数据保留、抓包上限或 Traffic Filter 匹配规则，只统一端点选择和连接生命周期的用户体验。

## Out of Scope

- 将所有现有底层连接持久化结构强制迁移为单一物理表。
- 自动给已有轻量 L2/L3 补齐四个端口。
- 自动推断复杂 VLAN Trunk、链路聚合、生成树或动态路由配置。
- 允许端口跨实验室连接或连接到当前单机管理范围之外的资源。
- 改变 QEMU、Docker、Bridge、NAT 或 netns 的底层转发原理。

## Delivery and Deployment Constraints *(mandatory)*

- **Local milestone**: 按“统一端点选择与手势”“统一连接提交与状态”“轻量设备默认四端口”“观察与恢复验收”拆分为可独立演示的本地里程碑；每个里程碑必须通过相关前端交互、契约、领域、运行时和回归测试。
- **Commit evidence**: 每个通过聚焦测试的里程碑必须形成独立 Git 提交，并记录提交 SHA、测试命令和结果；未提交或工作区不干净的构建不得部署。
- **Deployment artifact**: 从已记录的干净提交构建可复现部署制品，记录制品摘要、功能候选标识、构建时间和契约版本。
- **Target validation**: 将制品部署到 `10.72.1.7`，使用包含 QEMU、Docker、PC、轻量 L2、轻量 L3、Bridge 和 NAT 的实验室验证加号连接、端口拖拽、四端口默认值、实时接线、并发冲突、抓包、Traffic Filter、服务重启恢复和资源清理。
- **Rollback**: 部署前记录当前服务制品和配置；任一权威状态、运行时网络、共享客户端或资源清理验收失败时，恢复上一已验证制品并确认服务、既有实验室和连接恢复正常。
- **Target immutability**: Source fixes MUST NOT be made directly on `10.72.1.7`; failed validation returns to the local worktree for tests, a new commit, and redeployment.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在可用端口已存在的情况下，用户能够在 10 秒内通过拖拽或加号完成任意受支持资源组合的一次连接。
- **SC-002**: 至少覆盖节点到节点、节点到轻量对象、轻量对象到轻量对象、节点到 Bridge、节点到 NAT 五类连接的端到端验收，成功率达到 100%。
- **SC-003**: 新建轻量 L2 和轻量 L3 在未修改默认配置时均展示恰好四个可连接端口，且四个端口可以被分别占用和释放。
- **SC-004**: 用户使用加号和直接端口拖拽创建相同端点连接时，看到的目标选择、配置确认、状态反馈和最终拓扑结果保持一致。
- **SC-005**: 在 20 次连续连接、删除和重新连接循环中，不出现幽灵线条、不可复用端口、遗留运行时接口或错误端口占用。
- **SC-006**: 两个客户端并发争用同一端口时，最多一个连接成功，所有客户端在 2 秒内显示相同的权威结果。
- **SC-007**: 运行中的资源完成连接或删除时保持运行，且连接实际状态在正常主机负载下 3 秒内收敛为已连接或明确失败。
- **SC-008**: 拖拽端口的 50 次交互测试中，不发生节点意外移动、画布意外漂移、缩放突变或预览线锚点脱离源端口。
- **SC-009**: 每类统一连接均能被选择并完成一次抓包和一次 Traffic Filter 验证，未承载匹配流量的平行连接不会被错误高亮。
- **SC-010**: 服务重启后，已建立连接、端口占用和连接状态全部恢复；删除测试实验室后，与其关联的连接和运行时资源清理率达到 100%。
- **SC-011**: 键盘用户能够在不使用指针设备的情况下完成源端口选择、目标选择、连接确认和取消，且所有关键状态都有可感知反馈。
- **SC-012**: 既有实验室在升级后无需手工迁移即可加载，原有端口数量和连接关系保持不变。
