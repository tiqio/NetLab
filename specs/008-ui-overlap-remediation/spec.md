# Feature Specification: 全页面视觉与中文化治理

**Feature Branch**: `[008-ui-overlap-remediation]`

**Created**: 2026-08-06

**Status**: Draft

**Input**: User description: "全面排查项目中的元素重叠、文字与图形或控件交织、低对比度文字难以辨认等问题，重点优化检查器资源图、拓扑节点端口与加号、上下行文字、检查器按钮与状态标志、拓扑节点右键菜单等区域；同时检查仍未中文化的界面标识、说明、空状态、按钮、菜单和错误提示，例如 Console 中的 Right-click a node and choose Terminal，以及 Capture 相关文案。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 清晰操作拓扑节点与链路 (Priority: P1)

作为网络实验用户，我希望拓扑中的节点图形、名称、运行状态、接口端口、连接入口、上下行说明、链路标签、方向标记和流量效果彼此保持清晰间距，使我能够在节点较多、接口较多或缩放后的画布中准确识别和操作目标。

**Why this priority**: 拓扑画布是产品最核心的工作区。端口、加号、标签或状态标志重叠会直接造成误连线、误选节点和无法判断运行状态。

**Independent Test**: 创建包含 QEMU、Docker、PC、Bridge、NAT Bridge、Lightweight L2/L3 的代表性拓扑，并分别使用 1、2、4、8、16 个接口的节点检查显示与交互；无需依赖其他故事即可验证拓扑可读性和可操作性。

**Acceptance Scenarios**:

1. **Given** 一个节点同时显示资源图形、名称、状态和多个接口，**When** 用户以默认缩放查看并移动鼠标经过端口，**Then** 图形、文字、端口、连接入口和状态标志之间没有非预期遮挡，且每个接口都可被准确点击。
2. **Given** 两个节点具有多条并行链路，**When** 用户查看链路标签、方向和流量提示，**Then** 各链路可区分，标签不会覆盖端口或节点名称，方向信息不会与连接入口混淆。
3. **Given** 用户缩放、平移或拖动节点，**When** 拖动结束或视图稳定，**Then** 节点内部各视觉元素保持相对位置稳定，不出现文字跳动、端口漂移或控件相互穿插。
4. **Given** 节点名称、接口名称或链路说明较长，**When** 可用空间不足，**Then** 内容以可理解的截断、换行或按需展开方式呈现，完整内容仍可访问，且不会压住相邻控件。

### User Story 2 - 清晰阅读检查器与上下文菜单 (Priority: P1)

作为网络实验用户，我希望右侧检查器、节点右键菜单、链路菜单和各类状态面板中的标题、资源图、指标、按钮、颜色标志和说明文字在浅色与深色主题下都清楚可辨，以便可靠执行启动、停止、设置、终端、抓包、删除等操作。

**Why this priority**: 检查器和上下文菜单承载高频且具有破坏性的操作。按钮与状态标志重合或文字颜色过浅会导致误操作，也会让用户无法判断某项操作当前是否可用。

**Independent Test**: 在浅色和深色主题下依次打开节点、链路、网络对象和空画布的检查器与右键菜单，验证标题区、资源图、状态标志、按钮区和滚动区域，无需依赖拓扑布局改造即可独立验收。

**Acceptance Scenarios**:

1. **Given** 检查器顶部同时存在资源图、名称、状态颜色标志和多个操作按钮，**When** 检查器宽度处于最小支持宽度，**Then** 各元素按明确层级排列或换行，不发生遮挡，也不会把关键按钮挤出可视区域。
2. **Given** 检查器资源图下方展示 CPU、内存、接口、上下行或其他指标，**When** 指标值变长或语言文本变长，**Then** 图形与指标行保持独立区域，文本不会覆盖图形或彼此叠加。
3. **Given** 用户右键打开节点或链路菜单，**When** 菜单同时包含普通、禁用、危险和选中状态，**Then** 每项文字都具有足够对比度，图标与文字不重叠，状态差异不只依赖浅淡颜色表达。
4. **Given** 检查器内容超过可用高度，**When** 用户滚动查看后续设置，**Then** 标题、操作区和正文的固定或滚动关系明确，不会出现按钮覆盖字段、字段覆盖底部操作或内容无法到达。

### User Story 3 - 使用完整一致的中文界面 (Priority: P1)

作为中文用户，我希望导航、标签页、检查器、右键菜单、空状态、按钮、表单、状态、提示和错误信息都使用自然、一致且可操作的中文，使我不必在同一工作流中反复理解中英文混杂的描述。

**Why this priority**: 未翻译的关键指引和错误会直接阻断操作。例如终端空状态仍提示 “Right-click a node and choose Terminal”，抓包辅助程序错误仍以英文显示，用户可能无法判断下一步应该做什么。

**Independent Test**: 在不依赖布局修复的情况下，依次遍历实验室、模板、自动化、拓扑、检查器、右键菜单、任务、终端、抓包、流量过滤和诊断页面的默认、空、加载、成功、失败、禁用状态，检查全部用户可见文案及辅助说明。

**Acceptance Scenarios**:

1. **Given** 用户首次打开终端工作区且尚未创建会话，**When** 页面展示空状态，**Then** 标题、说明和操作指引均为中文，并明确提示通过节点右键菜单打开终端。
2. **Given** 用户进入抓包工作区，**When** 尚未选择来源、尚未开始抓包或本机 Wireshark 辅助程序不可用，**Then** 选择说明、操作按钮、状态和故障处理步骤均使用中文，且保留 Wireshark、pcap、pcapng 等必要技术名称。
3. **Given** 用户遍历模板选择、镜像导入、接口编辑、链路右键菜单、任务列表和流量过滤会话，**When** 出现空状态、禁用原因、工具提示、分页操作或错误，**Then** 不出现未经批准的英文句子或通用操作词，术语翻译在各处保持一致。
4. **Given** 服务端、宿主机工具或第三方程序返回英文原始错误，**When** 前端向用户展示该错误，**Then** 页面先提供中文问题摘要和可执行建议，并允许查看原始错误详情，而不是只显示无法理解的英文信息。
5. **Given** 使用屏幕阅读器或键盘浏览界面，**When** 聚焦图标按钮、关闭按钮、状态图和隐藏标题，**Then** 无障碍名称和辅助说明同样使用中文，且与屏幕可见文案含义一致。

### User Story 4 - 在不同窗口和主题下保持布局稳定 (Priority: P2)

作为使用不同显示器和窗口尺寸的用户，我希望主要页面、抽屉、对话框、底部工作区和图表在支持的窗口尺寸、浏览器缩放及浅色/深色主题之间切换时保持可读和可操作，而不是依靠刷新或重置恢复布局。

**Why this priority**: 当前重叠问题往往只在较窄窗口、长文本、主题切换或面板展开后出现，必须覆盖组合状态才能避免修复一个区域后在另一区域复发。

**Independent Test**: 使用标准视口和常见浏览器缩放依次遍历实验室、模板、自动化、拓扑、任务、终端、抓包、流量过滤与检查器状态，验证页面级溢出、元素碰撞和对比度。

**Acceptance Scenarios**:

1. **Given** 视口分别为 1024×768、1366×768 和 1920×1080，**When** 用户展开设备面板、检查器、操作抽屉和底部工作区，**Then** 主要操作仍可到达，页面不产生非预期横向滚动，面板之间不相互覆盖。
2. **Given** 用户从深色切换到浅色或从浅色切换到深色，**When** 菜单、下拉框、状态标志或图表处于打开状态，**Then** 前景与背景同步更新，不出现文字与背景同色、旧主题残留或内容重叠。
3. **Given** 浏览器显示比例为 100% 或 125%，**When** 用户完成创建节点、连接接口、打开检查器和使用菜单等关键流程，**Then** 控件不因放大而相互遮挡，操作顺序和结果保持一致。
4. **Given** 用户在终端、抓包、流量过滤和任务之间切换，**When** 底部区域隐藏、展开或恢复，**Then** 顶部拓扑、底部标签、工具栏和内容区边界保持清晰，不出现面板压住画布或标签消失。

### User Story 5 - 持续发现视觉与文案回归 (Priority: P3)

作为产品维护者，我希望有一套覆盖关键页面和密集状态的视觉与中文化审计基线，使新增文字、设备类型、状态标志或操作按钮不会再次造成遮挡、低对比度、不可点击区域或中英文混杂。

**Why this priority**: 全面治理只有形成可重复的检查范围和证据，才能避免后续功能迭代重新引入相同问题。

**Independent Test**: 对已定义的页面、视口、主题和高密度场景执行重复审计，并比较碰撞、溢出、对比度和关键操作结果，即可独立验证回归门禁。

**Acceptance Scenarios**:

1. **Given** 已建立关键页面与组件状态清单，**When** 执行视觉审计，**Then** 每个清单项都有通过、失败或明确豁免结果，并能定位到具体页面与元素。
2. **Given** 新增设备模板、状态标签或菜单项导致内容变长，**When** 执行回归检查，**Then** 非预期元素交叠、不可读文本和不可点击控件会被识别为失败。
3. **Given** 某些覆盖层属于有意设计，例如菜单、提示或拖动预览，**When** 审计发生，**Then** 只有可关闭、层级明确且不阻断目标任务的覆盖才可被接受，并需记录原因。
4. **Given** 新增或修改用户可见文案，**When** 执行中文化回归检查，**Then** 未列入技术术语或专有名称白名单的英文界面文本会被识别为失败。

### Edge Cases

- 节点具有 16 个接口、接口名称较长、多个端口同时处于已连接或高亮状态时，节点尺寸和端口分布仍需可辨。
- 节点名称、实验室名称、镜像版本、任务错误、资源 ID 或链路标签包含超长连续字符串时，不得撑破面板或覆盖操作按钮。
- 检查器宽度处于最小值，同时显示资源图、失败状态、危险操作和多行说明时，必须保持清晰层级。
- 右键菜单靠近视口右边缘或下边缘打开时，应自动保持在可见区域内，并避免文字与图标被裁切。
- 拓扑缩放到最小或最大支持级别时，低优先级标签可按规则隐藏，但端口、选中状态和关键操作入口不得互相覆盖。
- 多条平行链路、双向流量、粒子、箭头和 Traffic Filter 高亮同时出现时，不得让未承载流量的链路看起来处于活动状态。
- 浅色主题、深色主题、跟随系统主题以及主题切换瞬间都必须保持可读，不能出现白字白底、深字深底或状态颜色无法区分。
- 禁用、加载、失败、选中、悬停和键盘焦点状态同时存在时，状态表达不得互相抵消或只依赖颜色。
- 面板内容为空、加载中、发生错误或显示大量历史记录时，布局都不能坍塌或产生不可到达内容。
- 浏览器字体替换、中文文本变长或系统字号增大时，应优先换行、滚动或渐进隐藏次要信息，而不是相互覆盖。
- 服务端或第三方工具返回英文错误、状态码、命令和路径时，中文摘要不得覆盖或丢失原始诊断详情，原始详情也不得替代用户可理解的中文指引。
- QEMU、Docker、Wireshark、VNC、SSH、Telnet、TCP、UDP、IPv4、IPv6、DHCP、VLAN、pcap 等技术名称可保留，但其周围的按钮、状态和说明必须使用中文。

### Initial Localization Audit Findings

初步扫描已发现下列仍需纳入完整审计的用户界面区域；该清单用于确定最低覆盖范围，不代表允许忽略其他页面：

- 底部工作区仍混用 Tasks、Console、Capture 等英文标签，终端空状态仍显示 “Right-click a node and choose Terminal”。
- 终端会话中仍存在 Serial、Reconnect、Close 等通用操作或辅助文本。
- 抓包工作区的 Wireshark 辅助程序来源不匹配、程序未找到、连接超时和浏览器无法连接等错误仍存在完整英文句子。
- 模板选择和镜像导入仍存在 Select、unavailable、Basic runtime、NICs、Consoles、none、Name、Version、Runtime、Close 等通用界面词。
- 接口编辑、接口选择、创建资源和链路右键菜单仍存在 Interfaces、Cancel、Remove、Reconnect endpoint 等操作词。
- 任务历史分页、流量过滤图状态、拓扑悬浮说明和诊断隐藏标题仍存在 Show more、running、stopped、Click to select、Diagnostics 等英文文本。
- 图标按钮的关闭说明、工具提示、无障碍名称以及动态拼接的状态与错误需要单独检查，避免屏幕上已中文化但辅助技术仍读出英文。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 产品 MUST 建立覆盖全部现有主页面、工具栏、侧栏、抽屉、对话框、上下文菜单、检查器、底部工作区、图表和拓扑覆盖层的视觉审计清单。
- **FR-002**: 每个审计项 MUST 至少覆盖浅色和深色主题，以及 1024×768、1366×768、1920×1080 三种视口。
- **FR-003**: 关键创建、连接、检查、终端、抓包、流量过滤和删除流程 MUST 额外覆盖 125% 浏览器显示比例。
- **FR-004**: 产品 MUST 区分非预期碰撞与有意覆盖；有意覆盖必须可关闭、层级明确、不遮挡当前任务所需的目标，并在审计证据中说明。
- **FR-005**: 拓扑节点的资源图、名称、运行状态、选择状态、接口端口、连接入口、上下行说明和告警标志 MUST 拥有互不冲突的可视区域。
- **FR-006**: 拓扑节点 MUST 在 1、2、4、8、16 个接口的代表性配置下保持端口可辨、可点击，并避免端口、加号和接口文字相互遮挡。
- **FR-007**: 节点拖动、画布缩放、画布平移、自动适配和视图重置后，节点内部元素 MUST 保持稳定相对位置，不得出现漂移或短暂穿插。
- **FR-008**: 多条平行链路的线条、端点、标签、方向提示、流量粒子和 Traffic Filter 高亮 MUST 可区分，且不得覆盖节点主要文字或端口操作区。
- **FR-009**: 检查器顶部的资源图、标题、身份信息、状态颜色标志和操作按钮 MUST 在最小支持宽度下自动排列、换行或收纳，不得互相覆盖。
- **FR-010**: 检查器中的资源图表、指标行、上下行文字、表单字段、说明和底部操作 MUST 保持明确分区；内容超长时不得覆盖相邻区域。
- **FR-011**: 检查器、任务区、终端、抓包和流量过滤内容超过可用高度时 MUST 提供可到达的滚动区域，且固定区域不得遮住可滚动内容。
- **FR-012**: 节点、链路、网络对象和空画布的上下文菜单 MUST 在视口边缘自动保持完整可见，菜单项图标、文字、快捷键和状态标志不得重叠。
- **FR-013**: 普通、悬停、选中、禁用、危险、成功、警告和失败状态的文字与背景 MUST 保持可辨，并符合项目采用的可访问性对比度门槛。
- **FR-014**: 状态差异 MUST 同时通过文字、图形、边框或形态中的至少一种非颜色线索表达，不得仅依赖浅淡颜色。
- **FR-015**: 长名称、长接口名、长镜像版本、长资源 ID、长错误和长链路描述 MUST 使用一致的换行、截断、滚动或按需展开策略，同时保留完整内容的访问方式。
- **FR-016**: 所有可点击控件 MUST 保持独立点击区域；相邻控件的点击区域不得重叠，也不得被透明图层或装饰图形截获。
- **FR-017**: 键盘焦点 MUST 始终可见，且焦点轮廓不得被相邻元素、裁剪容器或覆盖层遮挡。
- **FR-018**: 页面和主要工作区 MUST 避免非预期的页面级横向滚动；确需横向展示的局部内容必须限制在明确且可键盘到达的滚动区域内。
- **FR-019**: 主题切换 MUST 同步更新文字、背景、边框、图表、菜单、下拉框、状态标志和拓扑语义色，不得残留旧主题颜色或产生同色文字背景。
- **FR-020**: 动画、加载状态、流量效果和状态过渡 MUST 不得导致稳定布局发生持续抖动、收缩、扩张或元素穿插；减少动态效果偏好下仍须完整可用。
- **FR-021**: 视觉治理 MUST 保持现有实验室、节点、链路和运行时权威状态不变；布局调整不得改变任何操作的服务端结果或跨客户端共享语义。
- **FR-022**: 多个浏览器客户端使用不同主题、不同窗口尺寸或不同面板展开状态时，客户端布局 MUST 相互独立，同时看到相同的权威资源状态。
- **FR-023**: 每个发现的问题 MUST 记录页面、元素、触发状态、视口、主题、严重程度、修复结果和回归证据，以支持全面清点和复验。
- **FR-024**: 阻断关键操作、隐藏状态、造成误点击或使正文不可读的问题 MUST 作为最高优先级处理；纯装饰性轻微偏移不得掩盖阻断问题。
- **FR-025**: 验收 MUST 包含至少一个高密度真实 Lab，覆盖 QEMU、Docker、PC、Bridge、NAT Bridge、Lightweight L2/L3、多接口、多链路、运行状态、失败状态和 Traffic Filter 高亮。
- **FR-026**: 验收完成后 MUST 删除专用测试 Lab 及其运行资源，同时保留目标机已有用户 Lab 和状态不变。
- **FR-027**: 产品 MUST 建立覆盖全部用户可见文案的中文化审计清单，包括导航、标签页、标题、正文、按钮、菜单、工具提示、占位文字、表单标签、空状态、加载状态、禁用原因、成功与失败提示、图表文字以及无障碍名称。
- **FR-028**: 除批准保留的技术术语、协议缩写、产品名称、设备型号、命令、路径和资源标识外，产品面向用户的句子、通用操作词和状态词 MUST 使用简体中文。
- **FR-029**: 产品 MUST 维护并一致使用核心术语对照，其中 Console 表达为“终端”、Capture 表达为“抓包”、Traffic Filter 表达为“流量过滤”、Tasks 表达为“任务”、Inspector 表达为“检查器”、Diagnostics 表达为“诊断”。
- **FR-030**: 终端和抓包工作区的空状态 MUST 使用中文说明当前缺少什么、用户应从哪里开始以及下一步可执行的操作，不得只显示英文引导或无操作价值的空白区域。
- **FR-031**: Wireshark 辅助程序不可达、来源不匹配、未找到 Wireshark、启动失败或抓包流不可用时，产品 MUST 提供中文问题摘要、中文处理步骤和可选的原始诊断详情。
- **FR-032**: 对服务端或运行时返回的已知状态、任务阶段、完成原因和常见错误，产品 MUST 显示一致的中文解释；未知原始值 MUST 以中文类别说明配合原始值展示，不得静默丢弃诊断信息。
- **FR-033**: 图标按钮、关闭操作、隐藏标题、焦点目标和其他仅供辅助技术读取的文案 MUST 使用中文，并与对应可见操作保持相同含义。
- **FR-034**: 中文化回归检查 MUST 能识别新增的非白名单英文界面文案，并允许对技术名称、协议、镜像名称和用户输入内容进行明确豁免。

### Key Entities

- **视觉审计场景**: 一个可重复的页面状态组合，包含页面或面板、主题、视口、显示比例、资源密度、交互状态和期望可见区域。
- **视觉碰撞发现**: 审计中识别的问题，包含受影响元素、碰撞类型、严重程度、复现步骤、是否阻断操作、修复状态和证据。
- **布局区域**: 具有明确边界和层级的视觉区域，例如拓扑节点内部、检查器标题区、菜单、图表区、工具栏或底部工作区。
- **可读状态**: 文字、背景、图标、边框、焦点和状态标志在特定主题与交互状态下的可辨识结果。
- **中文化审计项**: 一个用户可见或辅助技术可读的文案位置，包含所在页面、触发状态、原文、目标中文、术语类别、是否允许保留英文和验证结果。
- **界面术语表**: 产品核心概念的统一中文名称及允许保留的技术名称，用于约束标签、说明、错误和测试断言的一致性。
- **验收证据**: 修复前后对比、场景结果、失败原因、允许的有意覆盖、目标机结果和清理结果的集合。

## Delivery and Deployment Constraints *(mandatory)*

- **Local milestone**: 按拓扑核心、检查器与菜单、全局中文化、响应式与主题、自动化回归五个可独立验收切片推进；每个切片必须通过相关视觉、交互、键盘、对比度、中文化和既有功能回归。
- **Commit evidence**: 每个切片在部署前形成聚焦 Git 提交，并在验证记录中保存提交 SHA、覆盖场景和测试结果。
- **Deployment artifact**: 仅从干净提交生成可复现部署产物，记录源提交、候选标识、产物摘要、合同摘要和构建时间；本功能不引入数据库迁移。
- **Target validation**: 在 `10.72.1.7` 使用专用高密度 Lab 执行双主题、三视口、125% 显示比例和关键交互验收，并确保已有用户 Lab 不被修改。
- **Rollback**: 部署前保留上一已验证候选及目标配置；回滚后必须验证页面可访问、既有 Lab 可见、运行会话状态未被布局变更破坏。
- **Target immutability**: Source fixes MUST NOT be made directly on `10.72.1.7`; failed validation returns to the local worktree for tests, a new commit, and redeployment.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 视觉审计清单中的页面与关键组件覆盖率达到 100%，每个条目都有明确结果和证据。
- **SC-002**: 在双主题、三种标准视口和 100% 显示比例的验收矩阵中，阻断操作或遮挡正文的非预期元素碰撞数量为 0。
- **SC-003**: 在 125% 显示比例下，创建节点、连接接口、打开检查器、使用右键菜单、打开终端和开始抓包六类关键任务全部可以完成，且无控件因遮挡而不可点击。
- **SC-004**: 1、2、4、8、16 接口节点的全部可用端口均可被准确识别和点击，误触相邻端口或连接入口的次数为 0。
- **SC-005**: 浅色与深色主题下的关键文字、菜单项、状态标志和表单说明均通过严重级别可访问性对比度检查，严重或关键问题数量为 0。
- **SC-006**: 检查器、上下文菜单、设备添加抽屉、任务、终端、抓包和流量过滤在最小支持视口下均无页面级横向溢出，所有主要操作均可通过滚动到达。
- **SC-007**: 高密度拓扑中的并行链路、端口、方向、粒子和 Traffic Filter 高亮可被测试人员正确区分，未承载流量链路被误判为活动链路的次数为 0。
- **SC-008**: 主题切换、面板展开收起、路由切换和页面刷新各执行 20 次后，不出现文字与背景同色、布局漂移、控件重叠或需要 Reset 才能恢复的情况。
- **SC-009**: 布局治理前后，所有既有关键操作的权威资源状态和跨客户端可见结果保持一致，状态差异数量为 0。
- **SC-010**: 目标机验收结束后，专用 Lab 和其进程、容器、接口、链路、抓包及过滤资源残留数量为 0，已有用户 Lab 数量和身份保持不变。
- **SC-011**: 中文化审计清单覆盖的全部用户可见文案和无障碍文案中，非白名单英文句子与通用操作词数量为 0。
- **SC-012**: 终端空状态、抓包创建与 Wireshark 故障、模板选择、镜像导入、接口编辑、链路菜单、任务分页和流量过滤八类代表性流程均可仅依据中文界面完成，任务完成率为 100%。
- **SC-013**: 核心术语在导航、标签页、菜单、检查器、提示和测试断言中的不一致数量为 0；所有保留英文均能归入已记录的技术术语或用户数据豁免。

## Assumptions

- 本功能覆盖当前产品支持的桌面浏览器工作区，不以手机竖屏布局为目标；最小支持视口为 1024×768。
- 视觉治理优先保持 EVE-NG 类网络实验工作流的认知一致性，不进行无关的信息架构重做或品牌风格替换。
- 允许对次要信息使用截断、换行、局部滚动或渐进隐藏，但关键状态、端口和主要操作不得仅因空间不足而消失。
- 技术名称、设备名称、接口名称、地址、资源 ID、命令和错误原文保持原值；错误原文作为诊断详情保留，但其上方必须提供中文摘要和处理建议。
- 默认界面语言为简体中文；本功能不新增多语言切换能力，而是完成当前中文界面的覆盖与一致性治理。
- QEMU、Docker、Wireshark、VNC、SSH、Telnet、TCP、UDP、IPv4、IPv6、DHCP、VLAN、pcap、镜像名称和用户输入值属于允许保留的技术或数据内容，不应被机械翻译。
- 现有 API、MCP、事件、数据库和运行时生命周期合同保持不变；本功能只治理视觉布局、可读性和交互可达性。
- 目标机可能存在用户创建的 Lab；验收必须采用资源所有权和基线保护，只清理本功能创建的专用资源。
